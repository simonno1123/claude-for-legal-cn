### 包 C（T2、T3：依据时效包的格式与状态）

在 `china-litigation-core-rules.md` 开头的说明段落之后，增加一节"## 0. 依据时效包"，内容如下：

1. **存放位置。** 放在该案件的私有案件目录，文件名为 `依据时效包_<案件代号>_v<版本号>.md`，不得进入公开仓库。改版时另存新版本，旧版本保留。
2. **头部字段。** 案件代号、起草人、核对日、有效截止（核对日后第 30 日的 0 时，北京时间）、是否经复核人确认。
3. **每条规范一行，列为：** 序号｜规范全称、版本（修正年份）与条款｜拟用于｜适用时点（行为或事实发生的时间）｜状态｜来源层级与说明。
4. **状态只用以下七种：**

   | 状态 | 能否引用 |
   | --- | --- |
   | 已核对 | 可以 |
   | 律师已确认 | 可以 |
   | 部分核对 | 视为未经核对 |
   | 待核对 | 视为未经核对 |
   | 条号需对应现行法 | 视为未经核对 |
   | 可能已被取代（待确认） | 视为未经核对 |
   | 阻断 | 不得引用 |

   - **条号需对应现行法**：拟引用的规范以已修订的上位法为基础，其引用的上位法条号已经变动。
   - **可能已被取代（待确认）**：已有新的规范公布，或已公布征求意见稿，生效后将废止或替代拟引用的规范，但是否已施行尚未确认。
   - **缺口逐项消除。** 一条规范可能同时有几项缺口，例如条号需对应、正文只部分核对、现行状态未确认。每项缺口都在说明中单独列出；律师确认某一项，只消除这一项。全部缺口都消除之后，才能改为"已核对"或"律师已确认"。只要还有任何一项缺口，状态就按尚存缺口中最不利的一项填写，一律视为未经核对。
5. **时间效力。** 每条都要写"适用时点"。适用时点上有效的版本与现行版本不同的，两个版本分列两行，并说明本案适用哪一个；无法确定的，标为"待核对"。
6. **来源层级。** 沿用 C03 通用依据目录第二节的五层分级。

开头说明段落中"须在该案件的依据时效包中核对"一句之后，加"（格式见第 0 节）"。
