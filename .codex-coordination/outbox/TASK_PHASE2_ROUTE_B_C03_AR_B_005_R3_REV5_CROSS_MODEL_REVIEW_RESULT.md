## BLOCKING — 人工程序阻断

### J-01｜H 的来源和解除范围不完整，登记或查找可能漏掉应延续的停点

[修订五 L233–243](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L233-L243)要求每个停点都入 H，明确包括复核人自己发现的同类问题，却给每条记录同时要求「所在 M 和 X 的 SHA-256」，没有给无 X 的停点提供记录方式。旧停点的两条解除路径也以旧 X 或新版 X 为基础。另一方面，第 3 项只查询「全部未解除」，第 5 项在本候选得到实质修正后要求更新 H 状态，没有区分「原报告确属误报」和「只对某份新候选完成了修正」。[修订五 L180–185](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L180-L185)和 [修订五 L211–216](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L211-L216)要求 AI 只是咨询、重大冲突未解决即阻断；不能因索引无法表达来源或适用范围而漏掉先前事实。

**虚构反例一（人工发现、未发送）：** 复核人已形成 M 和 T，随后在准备 E 时发现期限相互矛盾，决定不送检，因此不存在 X。按字段表无法完整登记该人工停点。后来处理该案件的另一候选时，可以认真查完 H 却找不到它。拿不存在的 X 当作必填，也不能靠额外外发来补字段。

**虚构反例二（只修正某一版本）：** 候选 A 的 C5 触发停点。B 真正改正该争点，新 X 对该项通过，复核人据规则将 H 更新为「已解除」。候选 C 从 A 的旧材料另行生成，包含新内容却仍保留旧争点。查「全部未解除」不再返回该条；没有伪造或改编号逃避，只是把 B 的修正范围读成了整案解除，前置检查不再强制 C 证明实质修正。人审仍必须逐项检查，但不能替代本设计承诺的旧停点延续。

**修订要求：** 区分模型与人工来源：模型停点绑定确切 X；人工停点绑定 M、发生阶段、原件定位和私有发现记录，明确 X 不适用，而非留作未知。追加保存发现及解除事件，不覆写历史。区分证实原发现错误与仅对某候选／M 的实质修正；查找所有相关停点及其解除适用范围，只有能证明解除覆盖本次候选才不再阻断。人工发现的原件核验或实质修正也须有可执行的解除方式。若发送前出现新的相关停点，应重新查询或停止。该修订只需要明确人工字段与判断顺序，不需要 V8。

### J-02｜使用前 Q 尚未核对这份逐项授权本身仍然有效

[修订五 L365–387](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L365-L387)规定每份 Q 引用本次申请或授权，撤回对照却只明确列「候选、M 中材料、依据」。[修订五 L415–425](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L415-L425)要求 AR-B-010 绑定准确的记录链，防止换包配旧授权，但「引用正确授权」和「确认该授权仍生效」是不同判断。[前置关闭计划 L322–335](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_ACTIVATION_PREREQUISITE_CLOSURE_PLAN.md#L322-L335)明确逐项授权可以撤回，且不能推及其他用途。核对授权自身现状不能推迟到 [修订五 L403–413](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L403-L413) 的技术校验才有。

**虚构反例：** 项目所有者批准了虚构候选对某个内部动作的一次使用，随后只撤回这项授权，未撤回候选、M 或依据。使用前，复核人逐项对照 R/P，期限、资格和证据均无变化，引用的仍是同链的那份历史授权。Q 表所有列都可满足，但没有一列要求查这份授权的现行状态。若授权另设较早的截止时间，同样不能仅依 R/P 的截止判断。

**修订要求：** 明确按时间顺序留存：申请前 Q 引用已确定的申请事项；授权前 Q 引用这次待决申请，所有者在它通过后才作出逐项决定并将其与申请链绑定；使用前 Q 引用已签发的确切授权，并正面核验该授权仍有效、未撤回、未超出自身期限或次数、动作和范围完全相符。任一未知或不符，停止使用；不得用新的 Q 代替缺失或失效的授权。授权后的 Q 是追加核对记录，不替换所批准的原申请链。这样既不用预先引用尚未形成的决定，也不因补做 Q 而意外更换授权标的。

## NON-BLOCKING — 非阻断事项

- **NB-01｜把重新开始的说法统一到最早失效记录。** [修订五 L94–109](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L94-L109)规定 M 换包令旧引用失效，I 也绑定 M；「从 T 开始重做」不能解释为跳过新 I。[修订五 L373–391](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L373-L391)的「从新的 R」同理，前件失效时先补前件，不能仅新写 R。已失效的 I/T 若连带使 X 不可用，仍不得用等效重送补救；没有获准路径则保持阻断。按现有严格规则可安全执行，但宜把重做起点直接写清。等效人工确认也应明确如何留存逐项确认、签署主体及当时记录，不得以一般知悉代替 E-006。
- **NB-02｜抽查中的禁止重送应与送检禁令同口径。** [修订五 L438–443](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L438-L443)所称另行批准的跨模型审计不构成 [修订五 L235](https://github.com/simonno1123/claude-for-legal-cn/blob/515ee6db4411fb8dd69d69039c143a9b70897869/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L235)的一次发送例外。「来取得第二份 X」可能被读成只限制结果用途。建议明确同一 M 的 D 或等效包也不得以抽查为名重送；审计若另有范围，应与原裁定隔离、单独准入，且无安全路径时标记未完成。
