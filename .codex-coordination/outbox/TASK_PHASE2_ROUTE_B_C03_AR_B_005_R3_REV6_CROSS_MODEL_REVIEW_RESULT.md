### K-01｜L1 的「复核通过」证据与 H 解除、最终 R 的先后关系不确定

[修订六 L255–260](https://github.com/simonno1123/claude-for-legal-cn/blob/aeab85ea672d4c8ca5be3a37503e650115896873/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L255-L260)将 L1 的 `CORRECTED_IN_CANDIDATE` 证据定义为「复核人在 R 中对该项重新审查通过」；[修订六 L272–275](https://github.com/simonno1123/claude-for-legal-cn/blob/aeab85ea672d4c8ca5be3a37503e650115896873/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L272-L275)又规定解除事件形成之前不得作出 APPROVE。[修订六 L100–111](https://github.com/simonno1123/claude-for-legal-cn/blob/aeab85ea672d4c8ca5be3a37503e650115896873/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L100-L111)、[修订六 L376–378](https://github.com/simonno1123/claude-for-legal-cn/blob/aeab85ea672d4c8ca5be3a37503e650115896873/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L376-L378)只给出一个 R，它同时记载清单结果与处置；没有区分可先固定并引用的逐项重核证据与最终的 R。按已成文记录引用摘要的规则，若解除要以完成的 R 为依据、而完成的 APPROVE R 又必须等解除，便互为前件。若只依据未定稿的 R 字段，可以先写「通过」，但现文没有说明如何把当时的证据独立留存并绑定到最终 R。这是人工记载顺序歧义，不是要求数字签名。

**虚构反例：** L1 候选 B 已实质修正 A 的旧 C5 停点，T 已存前后对照。律师在纸面复核中确认通过，但无法依现文确定是先签带 APPROVE 的 R、再在 H 登记解除，还是先登记依赖尚未完成的 R 的解除。前者违反先解除才批准，后者没有已固定的重核证据。

**修订要求：** 为 L1 明确一条单向顺序：先固定与 M、T、发现事件绑定的逐项重核证据（或明确可独立留存的 R 前置记录），再追加 H 解除事件，最后形成含处置的 R 并引用证据和解除。不必新增代码。若 L1 沿用的是此前的模型停点，明确如何引用旧 X/V 作历史核验材料；不要求 L1 为解除重新送检，也不把旧 X 变成本轮独立检查。[修订六 L226–235](https://github.com/simonno1123/claude-for-legal-cn/blob/aeab85ea672d4c8ca5be3a37503e650115896873/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L226-L235)、[修订六 L376–378](https://github.com/simonno1123/claude-for-legal-cn/blob/aeab85ea672d4c8ca5be3a37503e650115896873/docs/phase2/route-b/TASK_PHASE2_ROUTE_B_C03_AR_B_005_HUMAN_REVIEW_GATE_PACKET_R3.md#L376-L378)目前未清楚衔接这一分支。
