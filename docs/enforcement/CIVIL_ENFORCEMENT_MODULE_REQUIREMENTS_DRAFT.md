# 中国大陆民事执行模块：案件驱动的需求与架构提案

> **状态：设计提案 / 待审阅。** 本文件仅沉淀可复用的业务需求与分析方法，不是法律意见，不创建或启用技能、代理、工作流、数据源、外部集成或生产能力，也不改变 Route A / Route B / C03 的现有治理状态。

## 1. 提案目的

为现有中国民商事诉讼能力补足一条可复用的民事执行分析主线。目标不是把“终本”“查财产”“写执行申请书”分别做成互不关联的提示词，而是建立从生效法律文书到财产发现、控制、处置、分配、恢复执行及衍生程序的完整分析闭环。

本提案仅使用抽象化业务模式和合成测试场景；不在公共仓库保存原始案件文件、真实当事人信息、案号、身份证件、地址、账号、具体财产标识、真实金额或可反向识别的案件时间线。

## 2. 项目定位与边界

### 2.1 在仓库分层中的位置

- **基础法律技能层：** 建议在 `litigation-legal` 中规划一个执行案件分析入口，负责识别材料、梳理事实与证据、核对执行程序、评估财产线索和生成待律师复核的分析初稿。
- **专业工作流层：** 跨案件的债务人/关联主体画像、资产台账、回款跟踪、任务分派、衍生诉讼储备和持续复核，适合由独立的专业律师工作流层承载；不要在基础插件中复制一套重型案件管理系统。
- **C03 执行领域审查设计：** 可在未来作为对分析候选进行反方压力测试和人工复核的治理层。它不是本提案的用户入口，也不因本文件而获得激活、材料处理、实施或生产运行授权。

### 2.2 本提案覆盖

1. 执行案件及关联案件的材料识别和状态重建；
2. 生效法律文书、执行依据、申请执行范围、已履行金额及剩余债权核对；
3. 被执行人及关联主体的身份与责任范围区分；
4. 财产线索的来源、权属、控制、价值、负担、期限和可处置性分析；
5. 终本审查、恢复执行、续封续冻、参与分配、破产衔接和执行异议相关程序的候选路径识别；
6. 执行款分配、历史回款及剩余债权核算；
7. 衍生诉讼触发点与补证清单；
8. 反方抗辩、法院审查重点、程序风险和人工确认门。

### 2.3 本提案不授权

- 自动查询或调查任何真实个人、企业、账户、住址、财产、行踪或通信；
- 联系法院、银行、平台、登记机关、管理人或其他第三方；
- 自动提交申请、起诉、执行异议、调查取证、保全或其他对外文书；
- 自动作出法律结论、诉讼策略、成功概率或是否立案/申请的最终决定；
- 将历史裁判文书中的个案处理方式固化为普遍法律规则；
- 变更现有 C03、Route A 或其他项目治理状态。

## 3. 从案件材料归纳的核心问题域

### A. 终本不是案件分析的终点

终本材料通常同时包含财产查询结果、已控制但暂不能处置的财产、限制消费/失信/拘留等措施、申请执行人意见和后续恢复执行提示。分析不能只复述“暂无财产”，而应区分：

- 是否确已完成必要的财产调查；
- 是否存在少量余额、保险现金价值或其他可处置收入；
- 车辆虽被查封但未实际扣押、无法控制或价值过低；
- 不动产因登记资料不全、权属争议或轮候查封而暂时无法处置；
- 已发现财产但存在首封、抵押、其他执行案件或处分障碍；
- 哪些查封/冻结仍有效、何时到期、是否需要续行；
- 终本后是否出现新线索、原障碍是否消除，以及恢复执行的材料基础。

系统应输出“已查明事实—未查明事项—暂不能处置的具体原因—可复核动作”，不得把法院文书中的“暂未发现”扩大为“客观上不存在”。

### B. 财产线索必须同时评价权属、控制、价值和处置

财产登记在被执行人名下，并不等于该财产当前就具有可回收价值；财产被查封，也不等于已实际控制或能够拍卖。每条线索至少需要回答：

1. **来源与权属：** 来源文件是什么，登记主体是谁，是否有冲突或第三人权利主张；
2. **控制状态：** 首封/轮候查封、冻结、实际扣押、占有使用、协助执行状态；
3. **价值：** 估值来源、估值日期、是否为询价或正式评估、是否存在不确定性；
4. **负担：** 抵押、优先权、其他执行案件、租赁/占有、税费和处分成本；
5. **可处置性：** 登记手续、产权证、权属争议、实物控制和法律限制；
6. **期限：** 查封/冻结起止、续行要求、处置程序进展；
7. **净回收判断：** 仅在必要数据齐全时估算可分配净值；数据缺失时标注未知，不得补造估值或抵押余额。

建议采用“发现障碍、权属障碍、控制障碍、处分障碍、价值/负担障碍、程序障碍、期限障碍、破产/政策障碍”的分类，而不是用单一的“有财产/无财产”字段概括。

### C. 多债权人分配应作为独立计算流程

案件材料显示，执行款可能来自不同被执行人的银行存款、保险现金价值或特定财产处置，也可能同时涉及多个执行案和债权人。模块必须把以下数据分开管理：

- 实际执行到位金额及来源；
- 执行费用、诉讼费用和其他依法先行扣除的金额；
- 依法优先受偿的债权及其依据；
- 参与分配的债权人、执行依据、参与分配金额和债权性质；
- 本次分配采用的基数、比例、舍入规则和计算日期；
- 已履行金额、历史分配金额、本次分配额和分配后余额；
- 分配方案送达日、异议期限及异议/复议/诉讼状态。

**执行程序中的参与分配与破产程序中的破产财产分配必须分开建模。** 两者的债权审查、清偿顺序、管理主体、程序节点和法律依据不同，不能因都存在“按比例分配”就共用一套不加区分的规则。

### D. 破产衔接应形成独立分流

公司进入破产程序、管理人无法取得账册、破产财产不足以支付破产费用、破产程序终结等情形，应触发程序状态核验，而不是直接输出“公司无财产，执行结束”。

建议核查：

- 破产申请/受理、宣告破产、债权申报与确认、财产分配、终结程序等阶段；
- 现有执行案件与破产程序之间的衔接状态；
- 已申报债权、已确认债权、分配结果及尚未清偿部分；
- 账册、资产、股东出资、关联交易、资产转移等材料是否存在缺口；
- 是否存在值得进一步调查的股东、清算义务人、实际控制人或其他主体责任线索。

此处只应生成“衍生责任调查触发点及所需证据”，不得仅凭破产终结或未取得账册就自动认定相关主体承担责任。

### E. 执行异议风险必须按时间线和权利类型分析

涉及第三人购买、拆迁安置权益、未完成初始登记或产权转移的财产时，不能仅以“登记在被执行人名下”直接判定必然可以处置，也不能仅以“已签合同、已付款”判定第三人必然可以排除执行。

至少需要并列核对：

- 原始权利来源及登记状态；
- 买卖合同订立时间、合同标的是否特定化；
- 付款凭证、剩余价款处理和款项是否按法院要求交付；
- 查封时间、第三人主张的合法占有/控制时间；
- 拆迁、认购、定位、交付、登记等行政或管理环节文件；
- 第三人是否存在其他权利、合同履行障碍或自身过错；
- 执行异议审查、执行异议之诉及后续裁判的具体理由。

输出必须区分执行异议的初步审查与执行异议之诉的实体审理，并将相反裁判理由作为风险测试，而不是只寻找支持己方立场的材料。

## 4. 建议的数据对象

| 对象 | 核心字段 | 设计目的 |
|---|---|---|
| `ExecutionMatter` | 内部事项ID、执行案号引用、执行依据、法院、程序阶段、状态日期、保密等级 | 管理一个执行事项及其状态变化 |
| `Entity` | 内部主体ID、主体类型、案件角色、身份来源、匹配置信依据 | 区分债务人、保证人、第三人、关联主体，避免仅凭同名合并 |
| `ClaimBalance` | 本金、利息口径、费用、已履行/已分配金额、计算截止日、来源 | 可追溯地核对债权余额 |
| `ExecutionAsset` | 财产类型、权属来源、登记主体、价值及日期、控制状态、负担、处分障碍、期限 | 从“财产线索”推进到“可执行性判断” |
| `ExecutionBarrier` | 障碍类型、事实依据、影响、解除条件、所需补证、责任人/复核状态 | 明确卡点和下一步需要解决的问题 |
| `ExecutionActionCandidate` | 候选动作、前置条件、证明目的、法律依据核验状态、期限、成本/风险、人工决定 | 形成可审查的行动清单，不自动执行 |
| `DistributionRecord` | 资金来源、可分配金额、扣除项、债权基数、比例、分配额、送达及异议状态 | 核对多债权人分配与回款 |
| `DerivativeTrigger` | 触发事实、可能路径、构成要件、证据缺口、反方解释、复核状态 | 将执行发现转化为待验证的衍生诉讼线索 |
| `EvidenceReference` | 文件标识/版本、页码或段落、原文摘录、待证事实、来源类型、冲突、核验状态 | 让每项结论都能追溯到具体材料 |

推荐把“事实”“法律事实”“证据评价”“法律规则”“行动候选”作为不同对象或状态。模型不得把文件中的陈述直接提升为已经证实的事实，也不得把待核实的线索直接提升为法律结论。

## 5. 建议的端到端分析流程

```text
材料清点与来源标记
        ↓
执行依据、债权余额与程序阶段核对
        ↓
主体关系及关联案件映射
        ↓
财产线索台账：权属 / 控制 / 价值 / 负担 / 期限
        ↓
执行障碍矩阵与终本充分性复核
        ↓
候选路径分流
  ├─ 继续执行 / 恢复执行 / 续封续冻
  ├─ 财产控制、处置与参与分配
  ├─ 执行异议 / 复议 / 执行异议之诉
  ├─ 破产债权申报与分配核对
  └─ 衍生责任调查与诉讼储备
        ↓
证据缺口、反方抗辩和法院审查重点
        ↓
待律师确认的行动清单与文书初稿
        ↓
人工确认、版本留痕与后续状态更新
```

每一个候选动作均应遵循既有工作流逻辑：**Input → Analysis → Decision Point → Evidence Requirement → Output**。如果缺少关键事实、法律依据、程序状态或期限起算点，应输出待核验事项，不得用默认值补齐。

## 6. 输出件的最小集合

1. **执行案件总览：** 执行依据、债权余额、程序阶段、已执行金额、未清偿金额、关键期限。
2. **财产线索矩阵：** 线索、来源、权属、控制、估值、负担、处分障碍、净回收数据完整性。
3. **终本复核表：** 法院已查措施、仍有效的控制措施、未处置财产、未覆盖的财产类别、可恢复执行触发条件。
4. **执行障碍矩阵：** 每项障碍的事实基础、影响、解除条件、需补证据和优先级。
5. **执行款分配复核表：** 资金来源、扣除项、债权基数、比例、计算过程、各案受偿与余额。
6. **衍生诉讼储备表：** 可能路径、构成要件、支持证据、缺口、反方抗辩和诉讼风险。
7. **行动计划：** 候选动作、所需材料、期限、成本/风险、是否需法院/第三方配合、律师确认状态。
8. **律师审阅备注：** 来源、读取范围、现行法核验、地方司法实践、未确认事项和人工确认门。

## 7. 法律规则与类案治理

- 现行法律、司法解释及其他有约束力的规范应优先于个案裁判说理和历史模板。
- 具体执行期限、参与分配条件、执行异议程序、破产衔接及强制措施适用条件必须在分析时核验现行有效性，不能照抄历史文书中的法条编号或期限。
- 对裁判实践的使用应遵守 `references/china-case-authority.md` 和 `references/case-authority-sources.json`：记录来源、层级、检索日期、相似点、区别点、可用范围及局限。
- 个案裁判仅用于校准风险和识别审查要点，不作为普通法意义上的拘束性先例。
- 所有法律文书、调查申请、保全、执行异议、分配异议、诉讼及其他对外动作均需具备相应资格的律师人工复核确认。

## 8. 迭代顺序建议

**第一步：文档与测试设计。** 先审阅本提案及合成场景，确定对象模型、输出格式、失效规则和人工确认门。

**第二步：最小基础技能。** 经单独批准后，在 `litigation-legal` 规划一个执行案件分析入口，先实现材料识别、程序状态重建、财产线索矩阵、终本复核和回款核算的初稿生成。

**第三步：专业工作流。** 在专业工作流层规划跨案件主体图谱、财产线索生命周期、任务跟踪、回款分配、破产衔接和衍生诉讼触发流程。

**第四步：独立回归与治理审查。** 使用合成测试覆盖财产处置障碍、分配计算、异议程序、破产分流、法律依据过期、证据冲突、跨事项污染及缺少人工批准等情形。任何技能实施、C03 激活、外部数据源或生产调用都必须遵循其各自的单独授权要求。

## 9. 提案验收标准

- 不把终本直接等同于“无任何财产”或“无后续动作”；
- 不把登记财产、查封财产与可立即处置财产混为一谈；
- 不遗漏财产价值、优先负担、控制状态和期限；
- 不混淆执行参与分配与破产财产分配；
- 不混淆执行异议审查与执行异议之诉；
- 不把潜在关联主体或破产事实直接等同于责任成立；
- 每项关键判断均能追溯至材料、页码/段落或待核验来源；
- 不以历史文书替代现行法核验；
- 对资料缺失、冲突、OCR 错误或来源不明作显式标记；
- 所有对外法律行动均保留人工确认门；
- 不改变本仓库既有治理状态，不上传或暴露真实案件材料。
