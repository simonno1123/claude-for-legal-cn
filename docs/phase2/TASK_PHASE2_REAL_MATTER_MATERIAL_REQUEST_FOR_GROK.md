# 真实案件材料需求（交 Grok bot 整理）

依据：`.codex-coordination/decisions/TASK_PHASE2_REAL_MATTER_STAGES_GROK_ROUTING_DECISION.md`。由 Grok bot 基于真实案件整理，由 Claude 在获得授权的阶段中使用。

**重要：材料含真实信息，只能放在所有者电脑的私有文件夹（建议 `Documents\legal-cn-private\`），不得上传到本公开仓库。**

## 一、每个案件包的统一结构

每个案件放在一个文件夹里，文件夹用不透露身份的代号命名，例如 `CASE-A`。文件夹内包含：

1. **`manifest`（清单）**：列出每份材料，每份写明以下各项：
   - 代号；
   - 材料类型（起诉状、判决书、执行裁定、证据、往来函件等）；
   - 来源：原件、复印件、扫描件或 Grok 整理稿；
   - 是否经过 OCR；
   - 日期；
   - 与本案的关系。
2. **原始材料或可读文本**：能提供原始文件的就提供原始文件；只能提供整理稿的，要标明"整理稿，非原件"。
3. **`facts`（事实摘要）**：只写材料中能找到依据的事实，每条注明出处，即哪份材料的哪一页。推测和结论不写在这里。
4. **`gaps`（缺口清单）**：列出缺少的材料、看不清的内容、身份不确定的当事人或文件。
5. **`parties`（主体表）**：列出当事人、代理人、法院、执行法院及各自的角色。这份文件同样只存放在私有文件夹中。
