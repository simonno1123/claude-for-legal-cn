### 控制措施的执行情况

1. **断网：** 识别在 `bwrap --unshare-net` 中运行。初始化、每一批识别和收尾前，共 11 次在同一隔离环境中访问外部地址，全部失败，失败记录已保存。
2. **系统调用跟踪：** `strace` 记录中没有任何 `connect` 调用。
3. **写入范围：** 运行前后私有目录文件清单一致（运行目录除外）。
4. **分批运行：** 宿主对单次命令有约 180 秒的时间限制，后台进程也不能保留，所以把一次运行分成"初始化 → 多批识别 → 收尾"三个阶段，使用同一个运行目录。每批都重新检查断网，并设时间预算，到时不再开始新图片。识别命令与参数始终不变。

## 三、输入处理检查（人工核对）

| 输入 | 应有表现 | 实际 | 是否符合 |
| --- | --- | --- | --- |
| 混合 PDF 第 1 页（有文字层） | 优先取文字层 | 文字层提取成功，内容与生成文本一致 | 符合 |

| 截断的 PDF | 明确报错 | `pdfinfo` 返回 1，报"找不到 trailer" | 符合 |
| 加密的 PDF | 明确报错 | `pdfinfo` 返回 1，报"密码错误" | 符合 |
| 不支持的格式 | 明确报错 | Tesseract 返回 1，报"处理出错" | 符合，但见下方注意 |

**注意：** 对不支持的格式，Tesseract 报错的同时仍会留下一个 0 字节的输出文件。今后的接入层必须以返回码判定成败，不能以"输出文件存在"判定成功，否则会出现"空结果冒充成功"。

## 四、补充复算（不改变结论）

评分规则在运行前已固定，结论只以上表为准。抽查清晰组的错误字段时发现两类评分上的偏差，所以用 `supplement.py` 事后复算，看结论是否取决于这些偏差：

1. **全角与半角：** 识别结果把全角括号、分号输出为半角。案号的错误全部属于这一类，案号本身的字符都识别对了。
2. **词框边界：** Tesseract 对中文的"词"往往把相邻的字连成一个框，按包含比例归入字段时，会带进字段前面的一两个字（例如金额前的"币"、日期前的"自"）。

复算方法：全角、半角统一（NFKC）后计算 CER；字段只要求标准答案完整出现在归入的文字中。

| 指标 | 原规则 | 补充复算 |
| --- | --- | --- |
| 清晰组 CER | 11.35% | 8.16% |
| 劣化组 CER | 28.78% | 26.18% |
| 清晰组关键字段 | 62.6% | 84.6%（77/91） |
| 全部版本关键字段 | 52.2% | 70.5%（385/546） |

复算后仍不到"有限"的门槛（清晰组 CER ≤ 8%，且错误覆盖率 ≥ 95%），结论不变。

**按样本类型的清晰组 CER（复算）：** 起诉状首部 0.5%，判决书段落 0.6%，对账单 0.7%，收据 9.5%，版面 18.9%，印章覆盖 18.8%。

**复算后仍然存在的实际识别错误**（清晰组）：
- 大写金额：三页全部出错，"叁"认成"参"，"仟"认成"什"，"柒""陆""捌"认成形近字；
- 印章覆盖：印章压住的金额、日期大多整体丢失，或者变成无关的字；
- 法条号："千"认成"干"，"第五百八十四条"漏成"第五百八十条"；
- 金额千分位：逗号认成句点或分号；
- 姓名：个别字认成形近字。

## 五、对后续工作的意义

1. 普通打印正文（起诉状首部、判决书段落、对账单）在清晰条件下错误率低于 1%，但对实务最要紧的大写金额、印章附近的日期和金额、法条号恰恰错误最多，而且置信度标记大多没有提示。
2. 翻拍和旋转造成的劣化最严重。真实材料中的手机翻拍件，用这一方案不可用。
3. 按设计第五节，转回 PaddleOCR 受控基准测试设计。可沿用本次的虚构样本、运行脚本和控制措施；评分规则建议在新设计中事先写明：
   - 全角、半角统一后比对；
   - 字段按字符级位置对齐，不按词框包含比例归入。

   两项都须在运行前确认。
4. 在另有方案通过之前，C01-V 包 V3 照常适用：图片内容只能由人工目视读取，或使用文字层，关键日期、金额、签章标 `[律师复核]`。
