## 〇、本轮的范围（先读）

本轮是**打印体图片中文识别的预筛选**，加上少量输入处理检查。即使结论为"通过"，也不代表已经完成复用评估第 8 节、PaddleOCR 评估第 11 节的全部候选评估门。下列能力本轮不测，继续保持"待验证"：

- 手写体；
- 真实签名和真实印章；
- 真实复杂版面。

它们只能在另行授权的真实材料抽样中评估，或者另做虚构样本设计。

## 一、为什么先试 Tesseract

- 复用评估（2026-08）当时在所评估的环境中没有发现任何识别引擎。
- 现状已经变化：所有者电脑上的 Claude 工作环境（Linux 虚拟机）里已有 Tesseract 4.1.1，但只有英文和方向检测两个语言包，没有中文。
- 只补一个中文语言包，就能检验现有引擎是否够用，不必另装框架。达不到标准的，再回到 PaddleOCR。

## 二、候选

| 项 | 内容 |
| --- | --- |
| 引擎 | Tesseract 4.1.1（已在环境中，不另装） |
| 语言包 | `chi_sim.traineddata`，取自 GitHub 上的 `tesseract-ocr/tessdata_fast` 主分支 |
| 取得方式 | 所有者本人在浏览器中下载，放入私有目录 `_tools/tessdata/`，记录 SHA-256。记录人所在的环境连不上 GitHub，不代为下载 |
| 加载方式 | 用 `--tessdata-dir` 指向该目录，不写入系统目录，不改系统设置 |
| 备选 | `tessdata_best` 中的同名文件（更大、更慢、通常更准），只在 fast 版结果为"有限"时另行评估 |

## 三、样本：只用虚构样本

由记录人在同一环境中生成，**不使用任何真实案件材料，也不使用真实个人信息**：

1. **字体：** 环境中已有的 Noto Serif CJK SC，以及同系列的无衬线字体（有就用）。
2. **样本类型**，每类 3 页，共 18 页：
   - 判决书段落：含法条引用，如"《中华人民共和国民法典》第五百七十七条"，以及按法院案号格式生成的虚构案号（年份、地区码、类型字和序号随机）；
   - 对账单表格：日期、品名、数量、单价、金额、合计，含千分位和小数；
   - 起诉状首部：虚构姓名、虚构身份证号格式字符串、地址、电话；
   - 收据或借条：大写金额（壹拾万元整）与小写金额并列；
   - 印章覆盖：用红色圆形和文字模拟印章，压在正文上；
   - 混排：中英文、全角与半角数字、标点混排；
   - 版面：双栏排版、页眉页脚、带合并单元格的表格。
3. **劣化版本**：每页再派生 5 个版本。
   - 低分辨率：150 dpi；
   - 旋转：±3°；
   - 模糊：轻度高斯模糊；
   - JPEG 压缩：质量 30；
   - 翻拍模拟：透视变形，加光照不均。
4. **标准答案：** 生成时同步保存逐行文本、字段清单（金额、日期、法条号、案号、证件号）、每个关键字段在图上的矩形框，以及表格的行列结构，作为评分依据。
5. **输入处理检查（不计入识别指标）：**
   - 混合 PDF：一页有文字层、一页只有图片；
   - 损坏文件：截断的 PDF；
   - 加密 PDF；
   - 不支持的格式。

   应有的表现：有文字层的页优先取文字层；只有图片的页才走识别；损坏、加密、不支持的输入明确报错，记入结果，不静默跳过，也不输出空结果冒充成功。
6. 样本与标准答案存放在私有目录 `_tools/ocr_benchmark/`；生成脚本与结果汇总可以入仓库，样本图片不入仓库。

**不覆盖：** 手写体、真实印章、真实复杂版面。这些只能在另行授权的真实材料抽样中评估。

## 四、指标

| 指标 | 定义 |
| --- | --- |
| 字符错误率（CER） | 编辑距离除以标准答案字符数，分"清晰"和"劣化"两组统计 |
| 关键字段完全匹配率 | 金额、日期、法条号、案号、证件号逐字段比对，只计完全一致 |
| 数字错误率 | 只统计数字和小数点的错误，单独列出 |
| 表格单元格匹配率 | 对账单类样本的单元格级别比对 |
| 失败页数 | 无输出或输出明显错乱的页 |
| 每页耗时 | CPU 运行时间 |
| 定位准确率 | 每个关键字段：先按"低置信度规则"中的包含比例归入词框，再把这些词框合并成一个矩形，与标准答案矩形的交并比（IoU）≥ 0.5 的，计为定位准确 |
| 置信度可用性 | 见第五节"低置信度规则" |

## 五、判定标准

| 结论 | 条件 |
| --- | --- |
| **通过** | 下列条件全部满足：清晰组 CER ≤ 3%，劣化组 CER ≤ 10%；清晰组关键字段完全匹配率 ≥ 98%；清晰组表格单元格匹配率 ≥ 95%；全部版本定位准确率 ≥ 95%；失败页数为 0；输入处理检查全部符合预期 |
| **有限** | 未达"通过"，但同时满足：清晰组 CER ≤ 8%；按"低置信度规则"，关键字段错误的覆盖率 ≥ 95%，且正确字段被标低的比例 ≤ 30%；输入处理检查全部符合预期。结构或定位不达标的，最高只能判"有限"。"有限"只能作为"识别候选"使用，关键字段一律人工核对 |
| **不通过** | 达不到"有限"的。转回 PaddleOCR 受控基准测试设计 |
| **立即停止** | 出现任何对外连接尝试，或在白名单（第六节第 2 项）以外写入 |

**低置信度规则（执行前固定，不得事后调整）：**
- 词级置信度取 TSV 中的 `conf`，低于 80 记为"低置信度"；
- 词与字段的对应用**包含比例**：一个词框有 ≥ 50% 的面积落在标准答案的字段矩形内，即归入该字段。不用单词与整个字段的交并比，因为多词字段中的每个词都会因面积差异而低于阈值。验算样例：一个字段被 5 个等宽词框完整覆盖，每个词框的包含比例都是 100%，全部归入该字段；
- 字段内有任何一个词为低置信度，该字段即算"被标低"；
- 字段识别错误且被标低的，算"已覆盖"；字段整体漏识别、找不到对应词的，算"未覆盖"；
- 覆盖率和误标率都按全部版本（清晰和劣化）统计。

无论结论如何，识别结果都只是候选：按 C01-V 包 V3 注明"识别（Tesseract 4.1.1 / chi_sim fast）"，关键日期、金额、签章标 `[律师复核]`。

## 六、控制措施

1. **运行期断网（执行前置条件）：** 识别命令一律在 `bwrap --unshare-net` 隔离环境中运行。每次运行前，在同一隔离环境中尝试访问一个外部地址，必须失败，并保存失败记录作为证据。隔离环境建不起来的，不运行。运行全程用 `strace -f -e trace=network` 记录网络相关的系统调用；出现任何对外连接尝试的，立即停止，该次结果作废，记录在案。
2. **访问白名单：** 隔离环境只挂载下列路径，其他路径一律不可见：
   - 只读：系统程序和库（`/usr`、`/lib` 等）；语言包目录 `_tools/tessdata/`；样本目录 `_tools/ocr_benchmark/samples/`。
   - 可写：本次运行的结果目录 `_tools/ocr_benchmark/runs/<运行编号>/`，临时文件也只放在这里。
   - 标准答案目录不挂载给识别进程，只由评分脚本在隔离环境外读取。

   停止条件相应改为：出现白名单以外的写入，或任何对外连接尝试。运行前后对私有目录做文件清单比对，作为写入范围的证据。
3. **可追溯：** 每次运行都记录引擎版本、语言包 SHA-256、命令参数、样本清单 SHA、开始和结束时间；原始输出（文本与 TSV）完整保留，不修改。
4. **定位信息：** TSV 中的页、行、坐标随结果一并保存，供人工比对原图。
5. **一次性：** 一次运行一组参数；改参数要重新记录，不覆盖旧结果。
