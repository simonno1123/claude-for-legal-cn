# 交给 Grok bot 的任务包（真实案件阶段）

所有者决定：需要真实案件材料的阶段，由 Grok bot 执行。决定记录见 `.codex-coordination/decisions/TASK_PHASE2_REAL_MATTER_STAGES_GROK_EXECUTION_DECISION.md`。本文件由 Claude 起草，所有者逐段复制、粘贴给 Grok 使用。

**用法：**
1. 每次开始一个新的 Grok 对话，先粘贴【包 0 通用规则】。
2. 然后粘贴要执行的那一个任务包。
3. Grok 完成后会给出一段"回传摘要"。把它粘贴回 Claude，由 Claude 记录进仓库。

**顺序：**
1. 包 1（案例 A）；
2. 包 4（执行案件包：AR-B-002 至 004）；
3. 包 5、包 6；
4. 包 2、包 3 视材料情况进行；
5. 包 7 要等到存在具体候选输出之后再做。

AR-B-001（C03 激活）由所有者本人决定，不交给 Grok。

## 【包 0 通用规则】（每个新对话先贴这一段）

```text
你将协助一名中国执业律师（民商事诉讼与民事执行方向）完成一个法律 AI 项目中“需要真实案件材料”的工作。请严格遵守以下规则：

一、身份与边界
1. 你只做材料整理、核对、登记和缺口识别，不出具法律意见，不作胜诉判断，不替律师作决定。
2. 任何对外发送、签署、提交、付款、删除、披露、跨境传输等有法律后果的动作，一律不做，只列出“需律师确认”的事项。
3. 真实身份、真实案号、身份证号、银行账号、地址、电话等，只在本对话内使用；在“回传摘要”中一律用代号替换（如 当事人P1、案件CASE-A、材料A-D01）。

二、证据纪律
1. 能读出来不等于真实；OCR 或你提取的文字只是“候选文本”，不是事实。
2. 每条事实必须注明出处（哪份材料、第几页或第几行）；没有出处的不得写成事实。
3. 文件、来源、案件、主体、用途五种身份分别判断，不得因为文件名或标签相似就合并。
4. 材料缺失、看不清、来源不明、身份不确定时，明确写“阻断”，不要推测补全。
5. 法律依据以现行有效的法律、司法解释为准，注明版本和核对日期；指导性案例、参考案例只能作参考，不能替代法律。

三、状态词（只用这些）
可用状态：已定位 / 文件身份已核验 / 文书审阅已完成 / 待律师复核 / 阻断。
阻断原因代码：来源不明、未找到、无权取得、需 OCR 未授权、提取未核对、案件身份不明、主体身份不明、集合缺少逐份身份、待文书审阅、待律师审阅、版本已被取代。

四、输出
每个任务结束时，先给出律师可直接核对的完整结果（可含真实信息，仅限本对话），然后单独给出一段“回传摘要”：
- 必须完全脱敏（只用代号，不出现任何真实姓名、名称、案号、证件号、账号、金额明细、地址）；
- 用表格列出：材料代号、类型、当前状态、阻断原因代码、下一步需要谁做什么；
- 末尾写明：本次没有执行任何有法律后果的动作。
```

## 【包 1】Route A 案例 A：补齐材料并登记

```text
任务：Route A 案例 A（代号 CASE-A）的材料恢复与登记。
当前状态：部分就绪；法律推理阻断。

需要处理的 4 项材料：
- A-D01 交易账单/对账工作簿：原路径缺失。请确认合法来源和保管人，取得原生副本（保留表格结构），登记版本，并计算 SHA-256。
- A-D02 公司/公示信息 PDF：已可读。只需确认来源和用途，并安排文书审阅。它不能替代交易类材料。
- A-D03 微信/往来记录：未找到。由律师确定合法来源和范围；尽量取完整导出，不要零散截图；消息与附件分开登记。
- A-D04 付款凭证：未找到。确认合法持有人和取得途径，逐份登记。

请输出：
1. 材料登记表：代号、类型、来源/保管人、取得途径是否合法授权、版本、SHA-256（能算则算）、状态、阻断原因。
2. 事实摘要：每条注明出处。
3. 缺口清单：仍缺什么，由谁、通过什么合法途径取得。
4. 需律师确认的事项清单。
5. 回传摘要（脱敏）。

完成标准：每项材料都处于明确状态（文件身份已核验 / 待律师复核 / 阻断+原因），没有任何“推定”的事实。
```

## 【包 2】Route A 案例 B：补齐材料并登记

```text
任务：Route A 案例 B（代号 CASE-B）的材料恢复与登记。当前状态：阻断。

需要处理的 5 项材料：
- B-D01 判决书/法院文书：原路径缺失。从法院或当事人等合法来源取得，核对版本，计算 SHA-256。
- B-D02 银行流水/财务记录：原路径缺失。先由律师确认取得资格和来源，再取原生记录，保留表格结构。
- B-D03 工商登记资料集：原目录不可用。只从合法来源重新取得；所依赖的每一份子文件都要单独登记，不能只记“一批”。
- B-D04 股东记录：还没有独立绑定的文件。从官方或公司来源取得，逐份、逐版本登记。
- B-D05 执行材料：未找到。由律师确定可以从法院或当事人取得的范围。

注意：不得根据原目录的文件数量或文件名推断材料内容。
输出要求与案例 A 相同：登记表、带出处的事实摘要、缺口清单、需律师确认的事项、回传摘要（脱敏）。
```

## 【包 3】Route A 案例 C：先确认案件身份

```text
任务：Route A 案例 C（代号 CASE-C）。当前状态：案件身份阻断，必须先由律师确认，再做其他事。

背景：这个案件存在多个可能指向不同事项的标签：一个现行验证标签、一个冻结时的执行衍生案件标签、一个历史文件名。它们不能自动合并。

第一步（必须先完成）：列出每个标签对应的案件、主体、程序（执行案件或衍生诉讼）及依据，请律师确认它们是同一案件还是不同案件。确认之前，不要取得或使用任何材料。

第二步（确认之后才做）：
- C-D01 费用明细工作簿：取原生副本，保留表格结构，计算 SHA-256。
- C-D02 财产/资产登记：确定合法的官方或当事人来源，登记确切版本。
- C-D03 执行记录/日志：确定可取得的程序范围。
- C-D04 衍生诉讼材料：确定合法来源和用途。

输出：身份核对表（标签→案件→依据→待律师确认结论）；第二步完成后，再按案例 A 的格式输出；最后附回传摘要（脱敏）。
```

## 【包 4】C03 执行案件包：Route A 就绪、案件与人员身份、证据准入（AR-B-002、003、004）

```text
任务：为“民事执行”能力（项目内代号 C03）准备一个真实执行案件的就绪材料包（案件代号 ENF-01）。C03 目前没有激活，本任务只准备材料，不运行任何分析。

A. Route A 就绪包（AR-B-002）
- 本案材料的来源确认、取得授权、是否被撤回；
- 材料清单的确切版本。
以下任一情况，标为阻断：清单是草稿、缺确认、无权取得、身份不明或混杂、只有 OCR 候选文本、人工复核未完成。

B. 案件与人员身份（AR-B-003）
请固定以下各项：
- 稳定的案件代号和版本；
- 操作人的角色代号（不需要真实姓名）；
- 授权来源，例如委托合同或授权委托书的代号；
- 授权的操作、对象、目的、有效期，以及是否已被撤回。
角色不清、授权过期、范围过宽，或收集了不必要的个人身份信息，都标为阻断。

C. 证据准入与来源矩阵（AR-B-004）
每份证据逐项列出：代号/版本/SHA-256、来源与取得方式、取得依据、就绪状态、局限、冲突、是否被撤回。
注意：不得把提取文本升级为事实；不同案件的材料不得混用。

输出：A、B、C 三张表；需律师确认的事项；回传摘要（脱敏，只含代号、状态和阻断原因）。
```

## 【包 5】合格人员复核关口（AR-B-005）

```text
任务：为 C03 的候选输出设计并记录“合格人员复核”的做法（复核关口包加复核人独立性记录）。

请列明以下各项：
- 复核人的角色代号；
- 资格依据（执业证类型和执业年限等，回传摘要中只写“已核”或“未核”）；
- 独立性：复核人不能复核自己生成的内容；
- 复核范围；输入和输出的 SHA-256；冲突与局限；禁止的用途。

允许的处置只有 4 种，原文照用：
REJECT / REQUEST CORRECTION / KEEP BLOCKED / APPROVE A SPECIFIC CANDIDATE FOR A SEPARATELY AUTHORIZED NEXT STEP
即使选择 APPROVE，也只表示可以另行申请下一步，下游仍然阻断。

以下任一情况，标为阻断：自己复核自己、角色不清、资格缺失、材料包不完整、存在未解决的重大冲突。
输出：复核关口说明、独立性记录、回传摘要（脱敏）。
```

## 【包 7】具体输出的下游授权（AR-B-010，等到存在候选输出后再用）

```text
任务：针对某一份具体的候选输出（给出代号、版本、SHA-256），整理一份“逐项下游授权决定包”，供律师本人决定。

需要写明以下各项：
- 该候选输出绑定的案件与目的；
- 复核人的处置（4 种之一）；
- 局限；禁止用途；
- 是否已被撤回；
- 拟进行的那一个下游动作。

只针对这一份输出、这一个动作，不得形成长期授权。
以下任一情况，标为阻断：候选输出缺失或已被取代、复核未完成、案件或目的发生偏移、输出主张了法律结论、授权范围不清。
输出：决定包（由律师本人签署决定）、回传摘要（脱敏）。
```
