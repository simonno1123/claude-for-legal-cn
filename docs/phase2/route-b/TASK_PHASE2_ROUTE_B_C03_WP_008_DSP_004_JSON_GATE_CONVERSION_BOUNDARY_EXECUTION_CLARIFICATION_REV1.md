## 2. 已发生的失败与诊断

1. 首轮外侧 WaitForExit(15000) 返回 false，随后终止自己创建的测试进程并返回，采集器抛出 ENTRY_TIMEOUT。该采集器未留存 child 正文，不得把未观察的场景数或输出量写为 0。
2. 逐场景内存诊断首次采用完整脚本 EncodedCommand，因 Windows 命令长度限制在启动前失败；随后仅编码短引导，将固定诊断文本经 stdin 传入。诊断完成，外侧观察 1669 ms，退出码 0，72 条进度标记覆盖 24 项。该运行有测试内存插桩，不替代未修改入口运行。
3. 未修改入口复跑的严格 UTF-8 stdout 读取任务报告 DecoderFallbackException。采集器仍未成功输出结构化归档，该失败单独保留；不能从未发出的元数据推断该次精确计时或停止状态。
4. 对同一首次入口采用原始字节读取后，实际退出码 0、stderr 0 bytes、外侧观察 2008 ms，保留 28662 个 stdout bytes，SHA-256 为 E0CB8977CF920D9B10C6D5F54AE091D5ED0F541473FD230CAEA7E1547300DD6B。严格 UTF-8 解码失败；严格 Code Page 936 解码可往返原字节，且中文合成输入精确匹配。
5. 原始字节证据确认该入口 File 执行路径的输出编码与严格 UTF-8 接收约定不相符，解释了接收管线故障。首轮 child 字节未留存，故不能独立证明首轮当次的唯一根因。
6. 原始字节诊断采集器曾把两个 CopyToAsync 的完成返回值写在其诊断 JSON 前；这两条外侧前缀已原样记录，不是 child stdout，也不混入合成判定。

不将这些实际失败改写为“首轮全部成功”或“零历史缺陷”。它们属于本批新测试入口／接收封装的失败与限制，不能自动归因为固定受测解析函数缺陷。

## 3. 后续本地复跑方式

以新的固定 PowerShell 进程通过 File 运行修正后的本批入口。外侧先按原始字节排空 stdout/stderr，再严格解码；不再让字符解码错误提前停止读取管道。仅在进程退出、字节完整取得并符合严格 UTF-8 后建立完整记录。

保留本次原始 stdout 的 gzip/base64 和身份，同时另留按 LF 规范化的结构化记录。接收侧核对原始字节到规范化文本的确定关系；不把本批测试进程输出保真扩张为生产 child 字节保真证明。

外侧仍使用 15000 ms 等待点，只是本批有限测试封装；不改变受测监督器的 120000 ms 预算或任何上游停止策略，也不宣称硬停止保证。若仍失败，保留观察，不静默提高预算或更改预期。
