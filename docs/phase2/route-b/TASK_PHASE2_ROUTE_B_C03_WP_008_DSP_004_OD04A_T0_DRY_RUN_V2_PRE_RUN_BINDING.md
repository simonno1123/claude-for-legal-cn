## 3. 运行前独立审查

审查者是另开的子任务，没有参与编写，但与记录人属于同一模型家族。

- **首次审查**：修好必须修改项后才能运行。v1 的发现中，IR-12 已解决，IR-04 解决到"记录并强制执行"，其余大多部分或基本解决；IR-03、IR-07、IR-14 未解决。
- **复核**：必须修改项和指出的问题均已正确实现，没有新增会阻断或误判的问题，代码层面可以运行。

两份审查原文完整保存在机器记录的 `PreRunReviews` 字段。

## 4. 预先声明的剩余限制

1. 同一账户下的程序可以篡改正在运行的监督程序或 Python 进程。文件锁和访问控制保护的是文件，不是进程（IR-03）。
2. 所有者账户是管理员。对管理员账户来说，用户账户控制不是安全边界。
3. 运行记录由监督程序写进用户可写的文件夹。由于不改动系统审计策略，没有由系统独立写下的旁证。
4. KnownDLLs 是开机时从内存段映射的，不是从被锁住的文件加载的（IR-07）。
5. 只运行一次，而且是在所有者的个人电脑上，不是记录中的验证机。
6. "子进程创建时间不早于 T0 前 50 毫秒"只证明这一点，不能证明更多。
7. 系统 DLL 的散列固定在 2026-10-31 的系统状态。运行前如果装了 Windows 更新，演练会被阻止。
8. 宿主进程中位于 `C:\Windows` 下的模块没有逐个核验签名（复核列为次要）。
9. Python 的源码导入闭包、运行参数和 `sys.path` 是子进程自报的，只作交叉核对。

**结果上限**：即使通过，按运行前审查的结论，这次结果最多是非证据性的工程观察。

## 5. 运行要求

- 在任何 Windows 更新之前运行。
- 所有者先以管理员身份运行 `install_v2.cmd`，再在资源管理器里双击 `C:\Program Files\DSP004Runtime\supervisor_v2\run_v2.cmd`。
- 如果有第三方安全软件向 PowerShell 注入 DLL，演练会被阻止。这是有意的"出错即停止"。

DSP-004 保持 `OPEN / HOLD`。B-01、B-02 保持 `OPEN`。
