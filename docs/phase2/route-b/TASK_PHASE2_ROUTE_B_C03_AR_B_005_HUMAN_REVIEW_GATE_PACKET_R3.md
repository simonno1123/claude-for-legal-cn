## 一、修订目的与总原则

R2 留下了一项局限：复核和放行集中在一人身上。在只有一名执业律师的前提下，这项局限无法消除。R3 的目标是**降低**一人判断出错的概率，并让错误更容易被发现。

总原则（以下各节都不得违反）：

1. **AI 永远不是复核人。** 复核人只能是合格执业律师，处置只能由人作出。任何模型的意见都只是参考。
2. **R2 是底线。** R3 只增加控制，不放宽 R2 的任何要求。R3 与 R2 有冲突时，按更严格的一方执行。
3. **L2 只是额外保护标签。** L2 不扩大 C03 的允许输出、允许用途或受众。R2 §八（升级边界）排除的事项，在 R3 下仍然排除；R2 禁止的用途不是"L2 路径"，AR-B-010 也不能推翻这些禁止。
4. **不确定即阻断。** 任何定级、证据、时间、绑定或外部状态无法确认的，一律阻断，不退回到更宽松的路径。
5. **最大正面结果只有一个：** 可以另行申请 AR-B-010 的逐项授权。R3 的任何控制都不构成授权、执行或解锁。

## 三、证据链：不可变输入与单向追加（对应 F-01）

### 3.1 两类对象

| 对象 | 内容 | 是否可变 |
| --- | --- | --- |
| **审查输入清单 M** | R2 §六 复核包的全部内容：候选输出、输入集、映射、遗漏、冲突、不利情况、依据、版本、禁止用途、留痕引用 | 一经形成即不可变。任何改动都是"换包"，产生新的 M |
| **追加记录** | 定级记录 T、外发准入记录 E、发送记录 S、交叉检查报告 X、复核事件 R、放行事件 P、停点解除记录 V、委托人凭证 K | 各自一经形成即不可变；只能新增，不能改写 |

### 3.2 单向引用顺序

```text
M → T → E → S → X → R → P
          （V、K 引用 M 与 T；R 引用 V、K）
```

- 每份追加记录都写明它所引用的前件的 SHA-256；**不把自身的摘要写进自身**。
- 追加记录不改变 M 的 SHA-256，因此合法追加不会使处置失效。
- M 改变（换包）时，所有引用旧 M 的追加记录全部失效，须从 T 开始重做。

### 3.3 哈希规则

- 材料文件：对原始字节计算 SHA-256。
- 记录：JSON 对象，按 RFC 8785（JCS）规范化后的 UTF-8 字节计算 SHA-256。
- SHA-256 一律写为 64 位大写十六进制。

### 3.4 设计版本绑定

每份追加记录写明设计版本三元组：设计代号 `C03-GATE-DESIGN-005`、**被采纳的 R3 正文 SHA-256**、清单版本 `CL-005-R2`。修订一、修订二、修订三的正文 SHA 不同，不能混用。

## 四、风险定级与允许用途（对应 B-01、F-04）

### 4.1 级别

| 级别 | 定义 |
| --- | --- |
| L1 内部底稿 | 只供复核人本人内部整理；不影响任何对外文书或委托人决策 |
| L2 受控底稿 | 复核人本人在 C03 之外自行起草文书或准备沟通时，作为内部参考 |

两级的**受众都只能是复核人本人**。候选在任何级别下都不得对外发送、转发、作附件或原样进入对外文书。

### 4.2 允许用途表（封闭）

只有下表所列组合是允许的。表外组合一律直接拒绝，不按 L2 处理。

| 用途代号 | 级别 | 允许的输出类别（WP-007 §16.1） | 受众 | 拟采取的下一步 | 所需委托人凭证 |
| --- | --- | --- | --- | --- | --- |
| U1 内部整理 | L1 | 全部 5 类 | 复核人本人 | 内部存档、整理（事实梳理、期限表、材料清单、冲突清单） | 无 |
| U2 起草参考 | L2 | `ISSUE_MATRIX`、`ADVERSE_CONDITION_REGISTER`、`CONFLICT_AND_INFORMATION_GAP_REGISTER`、`AUTHORITY_CHECK_REQUEST` | 复核人本人 | 复核人在 C03 之外**自行**起草文书；候选不原样进入、不作附件 | 无 |
| U3 沟通准备参考 | L2 | 同 U2 | 复核人本人 | 复核人在 C03 之外**自行**与委托人沟通；候选不转发 | 无 |

说明：

- 允许用途表只能通过修订本设计来增改，不能由调用方或单份记录填写。
- 目前三种用途都**不需要**委托人凭证，因为候选从不到达委托人。§八 的凭证机制保留，供今后经设计修订新增的用途使用（见第十五节确认事项 5）。
- 枚举表不能替代复核人对内容实质的审查：C6（禁止类别）、C7（法律结论）仍由复核人逐项判断。例如一份"方案比较"如果实质上是执行策略，属于 WP-007 §16.2 的禁止类别，应在生成和复核环节阻断，不能靠补凭证放行。

### 4.3 定级记录 T

- 由复核人形成，绑定：M 的 SHA-256、案件代号、候选代号、版本、输出 SHA-256、输出类别、用途代号、受众、下一步、设计版本三元组。
- L1 须复核人**正面确认**用途为 U1；不存在默认的 L1。

### 4.4 拒绝与重定级路径（理由码统一）

| 情形 | 处理 | 理由码 |
| --- | --- | --- |
| T 缺失；级别不在 {L1, L2}；字段互相矛盾 | 阻断，须重新形成 T | `TIER_INVALID` |
| 用途、输出类别、受众、下一步的组合不在允许用途表内 | 直接拒绝，不按 L2 处理 | `PURPOSE_PROHIBITED` |
| 用途未定、混合或冲突 | 按 L2 **评估**；但只有当组合落入 U2 或 U3 时，L2 允许用途才算**建立**；否则阻断 | `PURPOSE_NOT_ESTABLISHED` |
| 用途、受众、下一步、来源或范围发生实质变化 | 原 T 及其后全部记录失效，须重新定级、重新复核 | `BINDING_MISMATCH` |

"按 L2 评估"不等于"L2 允许用途已建立"。

## 六、跨模型交叉检查与停点（适用于 L2；对应 B-02、F-05、NB-02）

### 6.1 地位

- 执行者是另一家公司的模型，目前指定为 Codex；不得使用与生成者同一模型家族的模型。
- 交叉检查**只提供意见**：不作处置，不是复核人，不构成授权。"通过"不能替代复核人对 C1–C11 的逐项核验。

### 6.2 交叉检查报告 X

X 绑定：发送记录 S 的 SHA-256（从而绑定实际所见字节）、检查覆盖的清单项集合（C1–C11 中的明确子集）、模型提供方、模型标识与版本、收件时间。X 只用于本候选本版本，不跨候选、不跨版本复用。

每项意见取值只能是：`通过`、`不通过`、`无法判断-可见范围内`、`无法判断-脱敏盲区`。选"脱敏盲区"的，必须指明 §7.5 表中对应的盲区。

### 6.3 停点

底线：R2 §五 要求 C1–C11 全部通过才可能 APPROVE；R2 §十 要求未解决的重大冲突即阻断。

| 意见 | 适用项 | 处理 |
| --- | --- | --- |
| 不通过；或无法判断-可见范围内 | C5、C6、C7 | **硬停点** |
| 不通过；或无法判断-可见范围内 | 其他各项 | 停点 |
| 无法判断-脱敏盲区 | 任一项 | 该部分没有独立检查；复核人须以原件核验，并形成解除记录 V（类型 `ORIGINAL_VERIFICATION_OF_BLIND_SCOPE`）。这一部分的独立检查缺失列入局限（第十三节） |
| 缺项、取值不合法、结果互相矛盾、绑定不符 | 任一项 | X 视为未完成，L2 阻断 |

**停点的解除只有一种记录方式：** 解除记录 V，类型为 `MODEL_FINDING_REFUTED_BY_ORIGINAL`，逐条列出证据引用（材料登记代号、SHA-256、页码或行号）。每个证据引用的 SHA-256 必须出现在 M 的材料清单中。不允许用布尔值或一句"已解除"代替。

**另一条路是重新生成：** 通过 C03 生成新候选，从 M 开始重做全部流程。这不是"解除"，而是一条新的证据链。

以下做法都不构成解除：写异议说明、重复确认、等待 24 小时、在放行时点重新确认。

### 6.4 防止挑选结果（对应 NB-02）

- 同一 D 只能有一份 E、一份 S、一份 X；不得重复发送同一内容以换取更宽松的意见。已发出的 D 的 SHA-256 记入外侧的已使用标识登记（§十一 跨次防重放），重复即阻断。
- 同一候选系列因停点而重新生成的，每一版的 X 和停点都保留在私有记录中，不得删除；新版的 T 须写明前一版的候选代号和停点原因。
- 事后抽查优先抽取出现过停点的候选系列（§十二）。
- 脱敏盲区导致 C5 无法独立检查，是**可用性局限**，不是放宽停点的理由。

## 七、外发准入与发送（适用于 L2；对应 B-03、F-03）

### 7.1 关口在前

脱敏包交给任何第三方模型之前，须先形成外发准入记录 E，并按 §7.4 在发送前比对。**不通过即不发送**；L2 继续阻断，不回退到未脱敏外发，也不回退到 L1。

### 7.2 本地准备

1. **最小化：** 只保留交叉检查所需的结构和内容。
2. **直接标识：** 人名、名称、证件号、账号、地址、电话、案号一律用代号替代。
3. **间接标识与组合风险：** 检查罕见事实组合、精确日期与金额、财产线索、法院与地域信息、附件和文件元数据；能推断出案件或身份的，进一步泛化或删除。
4. **映射表不外发。** 代号与真实信息的映射只存本机私有目录。

代号替换**不等于**匿名化；脱敏包仍可能含个人信息。

### 7.3 外发准入记录 E（私有）

由所有者形成，绑定：

- 脱敏包 D 的**精确字节** SHA-256，以及 M、T 的 SHA-256；
- 允许发送的字段清单；
- 接收端：提供方、模型标识、调用入口或账户代号；
- 处理条件，须**逐项明确接受**：输入保留期限、是否用于训练、是否再共享、处理地域。"能确认会保留"不等于"已接受保留"；未逐项明确接受的，不发送；
- 有效窗口（起止时间）与撤回状态。

能否向第三方披露真实材料，由所有者依保密义务和个人信息保护规则另行判断；本设计不预设任何许可，也不以委托人知情、供应商国籍或仓库记录代替该判断。

### 7.4 发送前比对与发送记录 S

- 发送前，由外侧发送步骤把**实际要发出的字节**的 SHA-256 和**实际接收端**与 E 比对；在 E 的有效窗口内、E 未撤回，才发送。任一不符即不发送。
- 发送后形成 S，绑定：E 的 SHA-256、实际发出字节的 SHA-256、实际接收端、发送时间。
- V8 只读取已核验的 E → S → X 同一链路：E、S 中的 D 的 SHA 必须相同，X 必须引用 S。缺失、错绑或未知即阻断。V8 的结果不是发送授权。
- 已经发生的披露无法由事后检查撤回；因此防线在发送前比对，而不在 V8。

### 7.5 可核验范围

| 清单项 | 脱敏视图下模型能核验的范围 | 脱敏盲区（必须由复核人用原件核验） |
| --- | --- | --- |
| C1 案件一致 | 包内结构是否只指向一个案件代号 | 真实案件身份、是否混入其他案件 |
| C2 材料登记 | 引用是否都有登记代号 | SHA-256 与原件一致、证据矩阵状态 |
| C3 事实出处 | 每条事实是否标了出处 | 出处是否真实支持该事实 |
| C4 依据时效 | 是否引用了时效包、核对日期是否写明 | 依据是否仍有效 |
| C5 期限 | 期限是否被列出、相对顺序是否合理 | 真实日期和是否届满 |
| C6 禁止类别 | 内容是否落入禁止类别 | — （复核人仍须复核） |
| C7 法律结论 | 是否给出结论、意见或行动建议 | — （复核人仍须复核） |
| C8 强制提示 | 四项提示是否齐全、未改动 | — |
| C9 冲突局限 | 是否列明 | 原件中可见而未列出的冲突 |
| C10 个人信息 | 脱敏包内是否残留 | 原包的最少化 |
| C11 SHA 一致 | 见下 | 原包输入输出 SHA |

C11 区分三种证据，只有第三种能满足 C11：

1. 模型**看到了**某个摘要值；
2. 模型对其**所见的精确字节**独立复算了摘要（只证明 D 的一致性）；
3. 复核人对**原包**核验了输入输出 SHA-256，并在 R 中记录。

### 7.6 留痕

M、D、E、S、X 各自计算 SHA-256，在私有记录中相互绑定。公开仓库不记录任何一项。

## 八、委托人沟通凭证（对应 B-05、F-04）

1. **C03 之外。** 和解、拍卖、移送公安、恢复执行等委托人决定，仍按 R2 §八 排除在 C03 之外。复核人以独立核验的事实和自己的专业判断，在 C03 之外履行说明和沟通义务。
2. **不转发。** 候选、复核包和 AI 意见一律不转发给委托人，不作为给委托人的意见、指示或授权。
3. **两类凭证分开：** "已告知"（律师已就某事项向委托人说明）与"已取得明确指示"（委托人已就某事项作出决定）。
4. **需要哪一类由设计决定。** 只由 §4.2 允许用途表的"所需委托人凭证"一列决定，调用方不得留空或改填为"无需"。
5. **凭证 K 的绑定。** K 绑定：事项（案件代号）、所覆盖的具体动作、范围、类别、核实人、形成时间、有效状态。K 不得跨动作复用；所覆盖的动作与 T 中的下一步不一致的，阻断。
6. **地位有限。** K 只是外侧的私有记录；不能替代保密审查、第三方披露许可，也不能替代 AR-B-010 的逐项决定。委托人的指示针对委托人自己的决定，不是对候选内容的背书。
7. **公开仓库不记录。** 沿用 R2 §九 的最小留痕；不按候选公开凭证，也不写"已附"。

## 九、有效期与两个受控事件（对应 B-04、F-02）

### 9.1 时间的格式与来源

- 所有时间一律为带明确时区偏移的 ISO 8601 时间，按真实日历解析；没有时区偏移、日期不存在（例如 2 月 30 日）或无法解析的，阻断。
- 只有日期的期限，按北京时间（+08:00）该日 00:00 计（偏早，偏安全）。
- 事件时间、发送时间、收件时间和"当前时间"都须来自**受控时间来源**（§十一），并在当时形成。禁止事后补填。

### 9.2 有效截止（两级都适用）

有效截止 = 下列各项中**最早**的一个：

1. 依据时效包的核对日期（北京时间）后第 30 日的 00:00（+08:00）。依据时效包以其 SHA-256 和核对日期作为输入；
2. C5 所列每一项**适用**期限的届满时刻。

C5 的每一项期限须标明状态：`适用`（给出届满时刻）、`无适用期限`（须复核人在 R 中正面声明）、`未知`。任何一项为 `未知` 的，阻断。

截止**不含**届满的那一刻：必须 `当前时间 < 有效截止`。

### 9.3 事件 R（复核处置）

- L1 与 L2 都要有。绑定 M、T、（L2 时）X、V、K 的 SHA-256，处置原文，C1–C11 各项结果，重大冲突状态，C11 的原包核验记录，C5 期限清单与状态，依据时效包 SHA-256 与核对日期。

### 9.4 事件 P（放行复确认，仅 L2）

- 绑定 R 的 SHA-256。
- 复核人须**正面重核**并逐项记录三件事（不是"未发现变化"，而是"已重查"）：
  1. 复核结论仍然成立；
  2. C5 所列期限已逐项重查，没有变化（逐项列出重查结果）；
  3. 依据仍然有效（引用一份核对日期不早于 R 的依据重查记录）。

### 9.5 每次调用都要满足的时间条件

| 条件 | L1 | L2 |
| --- | --- | --- |
| `当前时间` 来自受控时间来源 | 必须 | 必须 |
| R ≤ 当前时间，且 `当前时间 < 有效截止` | 必须 | 必须 |
| X 收件时间 < R < P ≤ 当前时间 | — | 必须 |
| P − R ≥ 24 小时 | — | 必须 |
| P < 有效截止 | — | 必须 |
| P 含三项正面重核记录 | — | 必须 |

每次向 V8 提交（包括再次提交）都按当时的 `当前时间` 重新检查，不沿用上一次的结果。

### 9.6 重新计时

依据、期限、M、用途、撤回状态或资格声明状态任一发生变化，原 R 失效；复核重做后，从新的 R 重新计时，不得沿用旧起点。

### 9.7 期限紧迫

期限紧迫**不是**缩短 24 小时的理由，也不是由系统自动改走替代路径的理由。期限风险由律师在 C03 之外处理。

### 9.8 诚实说明

纯函数只能检查输入中的时间是否满足上述约束，**不能证明**律师真的等待了 24 小时，也不能证明期限清单完整。同一律师的两次事件也不等于两名独立复核人。

## 十、代码强制（V8 拟实现范围；对应 B-06、F-01 至 F-05）

V8 另行实现、审查、正式运行。本节只定义合同。

### 10.1 纯函数边界

所有检查都是纯函数：函数本身不读时钟、不访问网络或文件、不持久化。"当前时间"作为受控时间记录传入，由函数校验其签名（§十一）。

函数**能**做：校验封闭输入中的类型、哈希格式、签名、同一性、先后顺序、规则和前置条件。
函数**不能**做：自行访问外部系统、确认身份、认定脱敏是否充分、证明真实等待、发现调用方没有提交的撤回。

### 10.2 封闭输入记录

函数只接受一份封闭的输入记录：字段固定，不接受多余字段，每个字段有固定类型。

| 组 | 字段 |
| --- | --- |
| 设计版本 | 设计版本三元组（§3.4） |
| M | M 的 SHA-256；材料清单（登记代号 → SHA-256）；案件代号、候选代号、版本、输入集 SHA-256、输出 SHA-256、输出类别 |
| T | §4.3 全部字段 |
| R | §9.3 全部字段 |
| L2：E、S、X、V、P | §7.3、§7.4、§6.2、§6.3、§9.4 全部字段 |
| K | §八 第 5 项全部字段（仅当允许用途表要求时） |
| 生成记录 | 生成者代号、生成模型提供方与模型家族、生成运行记录 SHA-256 |
| 外侧状态 | 撤回状态快照（含形成时间）、防重放标识 |
| 签名 | 上述每份记录的签名与签名人代号 |
| 当前时间 | 受控时间记录 |

### 10.3 校验规则

1. 设计版本三元组与被采纳的 R3 一致。
2. 每份记录的签名有效，签名人是该记录的法定形成人（§十一）。
3. 单向引用链完整：每份记录引用的前件 SHA 与实际前件一致；不存在环。
4. 所有绑定字段在各记录之间一致。
5. 输出类别在 WP-007 §16.1 允许集合内；（用途、输出类别、受众、下一步）组合在 §4.2 允许用途表内。
6. 处置为 R2 §七 的 4 种原文之一；只有 APPROVE 才可能得到正面结果。
7. C1–C11 全部为"通过"；C11 有原包核验记录；重大冲突状态为"无"；撤回／取代状态为"无"。
8. 复核人代号已登记、资格与独立性声明引用有效，且复核人不是生成者。
9. L2：交叉检查模型家族 ≠ 生成模型家族；E → S → X 链路一致；§6.3 每个停点都有类型正确、证据引用都在 M 材料清单中的 V；§9.5 的时间条件全部满足。
10. 允许用途表要求凭证的，K 存在、类别正确、覆盖的动作与 T 的下一步一致、状态有效。
11. 撤回状态快照的形成时间晚于 R（L2 时晚于 P），且距当前时间不超过所有者确定的上限；否则视为不可信。
12. 防重放标识未在本次输入的其他记录中出现过；跨次调用的防重放由外侧负责。

### 10.4 输出

- **阻断**：附理由码。理由码为封闭集合：
  `DESIGN_VERSION_MISMATCH`、`SIGNATURE_INVALID`、`CHAIN_BROKEN`、`BINDING_MISMATCH`、`TIER_INVALID`、`PURPOSE_PROHIBITED`、`PURPOSE_NOT_ESTABLISHED`、`OUTPUT_CLASS_NOT_PERMITTED`、`DISPOSITION_NOT_APPROVE`、`CHECKLIST_NOT_ALL_PASS`、`C11_ORIGINAL_NOT_VERIFIED`、`MATERIAL_CONFLICT_OPEN`、`WITHDRAWN_OR_SUPERSEDED`、`REVIEWER_INVALID`、`SAME_MODEL_FAMILY`、`EGRESS_CHAIN_INVALID`、`CROSS_CHECK_INCOMPLETE`、`CROSS_CHECK_STOP_UNRESOLVED`、`DEADLINE_STATUS_UNKNOWN`、`VALIDITY_EXPIRED`、`EVENT_ORDER_INVALID`、`COOLING_PERIOD_UNMET`、`RECONFIRMATION_MISSING`、`CLIENT_RECORD_MISSING`、`TIME_UNTRUSTED`、`EXTERNAL_STATE_UNTRUSTED`、`REPLAY_SUSPECTED`。
- **最大正面结果**：`ELIGIBLE_TO_REQUEST_AR_B_010`，即"可以另行申请 AR-B-010 的逐项授权"。该结果不是授权，不执行任何动作，不解锁下游。
- **下游独立校验。** AR-B-010 的执行边界不信任调用方转述的结果：它须自行对同一输入重新运行 V8，并独立核对所有者对该候选、该动作的逐项授权。没有这一步，下游始终阻断。

## 十一、外侧事实的交接合同（对应 F-05）

| 外侧事实 | 责任主体 | 可信输入类型 | 来源绑定 | 不可核验时 |
| --- | --- | --- | --- | --- |
| 复核人身份、资格、独立性声明 | 所有者 | 所有者签署的声明记录（R2 E-006） | 声明 SHA-256；登记的签名公钥 | 阻断 `REVIEWER_INVALID` |
| 生成者及生成模型家族 | 所有者 | C03 生成运行记录（所有者签署） | 运行记录 SHA-256；输出 SHA-256 | 阻断 `EXTERNAL_STATE_UNTRUSTED` |
| 交叉检查模型的来源 | 所有者 | 接收端返回的元数据（提供方、模型标识、请求标识），写入 S 与 X 并签署 | S、X 的 SHA-256 | 阻断 `SAME_MODEL_FAMILY` 或 `EGRESS_CHAIN_INVALID` |
| 外发准入、发送前比对、实际发送 | 所有者 | E、S（所有者签署） | §7.4 链路 | 阻断 `EGRESS_CHAIN_INVALID` |
| 收件时间、事件时间、当前时间 | 所有者 | 受控时间来源的记录（候选：RFC 3161 时间戳服务，或所有者另行指定的等效来源） | 时间记录绑定所盖时间的记录 SHA-256 | 阻断 `TIME_UNTRUSTED` |
| 停点解除的证据 | 复核人 | V（签署），证据引用指向 M 材料清单 | M 的 SHA-256 | 阻断 `CROSS_CHECK_STOP_UNRESOLVED` |
| 委托人凭证 | 复核人 | K（签署） | 事项、动作、范围 | 阻断 `CLIENT_RECORD_MISSING` |
| 依据时效 | 复核人 | 依据时效包与重查记录（签署） | 时效包 SHA-256 与核对日期 | 阻断 `VALIDITY_EXPIRED` |
| 撤回状态 | 所有者 | 撤回状态快照（签署，含形成时间） | 快照覆盖的全部记录 SHA-256 | 阻断 `EXTERNAL_STATE_UNTRUSTED` |
| 跨次防重放 | 所有者 | 已使用标识的私有登记 | 标识与 M 的 SHA-256 | 阻断 `REPLAY_SUSPECTED` |
| AR-B-010 逐项授权 | 所有者 | 逐项授权记录（签署） | 候选、动作 | 下游阻断 |

签名：每份记录由其形成人用登记的私钥签名（候选算法 Ed25519）；登记的公钥及其状态记入私有记录。V8 只校验签名与登记公钥是否一致。

**诚实说明：** 目前只有一人持有签名密钥。签名只证明"所有者签了这份记录、签后未被改动"，不证明记录内容真实。

## 十二、事后抽查（对应 NB1、NB-01）

1. **范围：** 每个自然季度（北京时间）内作出处置的候选。同一候选的多个版本，只计最后一个作出处置的版本。季度标识写作 `YYYYQn`，例如 `2026Q4`。
2. **数量：** n = 向上取整（该季度候选数 × 10%），且不少于 2；候选数不足 2 的全部抽查。
3. **唯一选样算法：**
   1. 种子 = SHA-256（UTF-8 字节 `C03-AR-B-005-SAMPLE|` + 季度标识），取 64 位大写十六进制。
   2. 每个候选的分值 = SHA-256（UTF-8 字节 种子 + `|` + 候选代号），取 64 位大写十六进制。
   3. 分成三组，依次抽取：第一组为出现过停点的 L2 候选系列，第二组为其余 L2，第三组为 L1。每组内按分值升序排序；分值相同时按候选代号的 Unicode 码位升序。
   4. 依次从第一、二、三组取，直到取满 n 份或取完。
4. **抽查者：** 跨模型交叉检查（只看经 §七 准入的脱敏包），或经所有者另行同意的同行律师。某份样本不能外发、也没有同行律师的，记为"未完成抽查"并说明原因，不得用其他样本替代，也不得改由复核人自查后记为完成。
5. **留痕：** 种子、全部候选的分值、抽取结果写入私有记录。同一季度、同一候选清单必然得到同一结果。
6. **结果：** 只用于改进。尚未执行的事项仍按 R2 §十 处理撤回；已执行的事项不自动改写历史，也不自动改变既有决定，发现问题时另行评估。发现系统性问题的，须修订本设计。

## 十三、仍然存在的局限

R2 采纳决定所列的局限**全部保留**：复核人身份与资格是本人声明；独立性只是部分独立；复核人参与了输入的准备。此外：

1. 复核与放行的最终决定权仍在一人。R3 只是**拟缓解**，没有消除集中。在 V8 实现并正式运行、外侧控制有证据之前，记录时一律写"拟缓解，未验证"。
2. 同一律师的两个时点不等于两名独立复核人。
3. 交叉检查只看脱敏材料。对脱敏盲区（尤其是 C5 的真实日期、C11 的原包摘要），交叉检查**没有提供任何独立检查**；这些部分仍只依赖复核人一人。
4. 跨模型检查与生成模型也可能犯同样的错。
5. 代码只检查记录是否齐全、一致、签名有效，不检查判断本身是否正确。
6. 签名密钥由一人持有；签名不证明内容真实。
7. 受控时间来源、签名密钥登记、撤回传播、跨次防重放目前都尚未建立，也未核验。
8. 此前各轮审查中，有同模型审查，也有两轮 Codex 跨模型设计审查；均为文本审查，不是对实际运行的验证。本稿不改写这一历史。
