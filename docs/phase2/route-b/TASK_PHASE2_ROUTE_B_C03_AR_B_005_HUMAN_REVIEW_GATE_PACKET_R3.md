## 一、修订目的与总原则

R2 留下了一项局限：复核和放行集中在一人身上。在只有一名执业律师的前提下，这项局限无法消除。R3 的目标是**降低**一人判断出错的概率，并让错误更容易被发现。

总原则（以下各节都不得违反）：

1. **AI 永远不是复核人。** 复核人只能是合格执业律师，处置只能由人作出。任何模型的意见都只是参考。
2. **R2 是底线。** R3 只增加控制，不放宽 R2 的任何要求。R3 与 R2 有冲突时，按更严格的一方执行。
3. **L2 只是额外保护标签。** L2 不扩大 C03 的允许输出、允许用途或受众。R2 §八（升级边界）排除的事项，在 R3 下仍然排除。
4. **不确定即阻断。** 任何定级、证据、时间、绑定或外部状态无法确认的，一律阻断，不退回到更宽松的路径。
5. **最大正面结果只有一个：** 可以另行申请 AR-B-010 的逐项授权。R3 的任何控制都不构成授权、执行或解锁。

## 三、风险定级（新增；对应 B-01）

### 3.1 级别

| 级别 | 定义 |
| --- | --- |
| L1 内部底稿 | 只供复核人本人内部整理使用；不进入任何对外文书，不向委托人或任何第三方转发，不作为委托人决策的依据 |
| L2 受控底稿 | 除 L1 外的一切情形，包括：可能被用作对外文书的素材、可能影响委托人决策、用途未定、用途混合或用途互相冲突 |

L2 是**更严的保护标签**，不是"可对外使用"的许可。即使是 L2，候选本身也不得对外发送或转发（见 §七）。

### 3.2 L1 的正面确认

L1 不是默认值。只有同时满足下列条件，才可以定为 L1：

1. 由复核人（合格执业律师）在定级记录中**正面确认**，并写明一项具体、限定的内部用途。
2. 定级记录绑定：候选代号、版本、输出 SHA-256、复核包 SHA-256、案件代号、用途、受众（只能是"复核人本人"）、拟采取的下一步、设计版本 `R3` 和清单版本 `CL-005-R2`。
3. 用途属于 L1 允许的封闭清单：事实梳理、期限表、材料清单、冲突清单。清单之外的用途不能定为 L1。

以下情况一律按 L2 处理；如果连 L2 的允许用途也无法建立，直接 KEEP BLOCKED：

- 定级记录缺失、取值不在 {L1, L2} 之内、字段之间互相矛盾；
- 用途未知、混合或冲突；
- 定级人不是已登记的复核人，或定级人是生成者。

### 3.3 用途漂移

- 用途、受众、来源或范围发生任何实质变化，原定级和原处置**同时失效**，须重新定级、重新复核。
- 输出 SHA-256 不变并不能保住原处置：处置绑定的是"候选 + 用途 + 受众 + 下一步"的整体。
- 不允许事后补记 L1，也不允许把 L1 处置沿用到新用途。
- 用途漂移按 R2 §十 作为撤回事由处理。

## 五、跨模型交叉检查与分歧停点（适用于 L2；对应 B-02）

### 5.1 地位

- 执行者是另一家公司的模型，目前指定为 Codex；不得使用与生成者同一模型家族的模型。
- 交叉检查**只提供意见**：不作处置，不是复核人，不构成授权。
- 交叉检查判为"通过"，**不能**替代复核人对 C1–C11 的逐项核验。

### 5.2 输入与结果绑定

- 只接收经 §六 准入的脱敏复核包。
- 交叉检查结果绑定：候选代号、版本、输出 SHA-256、原复核包 SHA-256、脱敏包 SHA-256、检查范围（C1–C11 中哪些项）、模型与版本标识。
- 结果只用于本候选的本版本，不跨候选、不跨版本复用。

### 5.3 停点

底线：R2 §五 要求 C1–C11 全部通过才可能 APPROVE；R2 §十 要求未解决的重大冲突即阻断。在此之上：

| 交叉检查对某项的意见 | 适用项 | 处理 |
| --- | --- | --- |
| 不通过 | C5（期限）、C6（禁止类别）、C7（法律结论或法律后果） | **硬停点。** 只有两条路可以解除：（a）复核人用已绑定的原始依据（登记代号 + SHA-256 + 页码或行号）证实是模型误报，并在复核包中逐项写明；（b）通过 C03 重新生成新候选，并重做所需的全部复核。做不到的，只能 KEEP BLOCKED、REQUEST CORRECTION 或 REJECT |
| 不通过 | 其他各项 | 同上（a）或（b）；做不到的，不得 APPROVE |
| 无法判断 | C5、C6、C7 | 按"不通过"处理 |
| 无法判断 | 其他各项 | 复核人须用原件独立核验该项并写明依据；不能核验的，不得 APPROVE |
| 缺项、结果互相矛盾、绑定不符 | 任一项 | 交叉检查视为未完成，L2 阻断 |

以下做法**都不构成**解除停点：单纯写异议说明、重复确认、等待 24 小时、在放行时点重新确认。

## 六、外发准入关口（适用于 L2；对应 B-03）

### 6.1 关口在前

脱敏包交给任何第三方模型之前，须先通过本关口。**本关口不通过，就不传输**；L2 继续阻断，不回退到未脱敏外发，也不回退到 L1。

### 6.2 本地准备

1. **最小化：** 只保留交叉检查所需的结构和内容。
2. **直接标识：** 人名、名称、证件号、账号、地址、电话、案号一律用代号替代。
3. **间接标识与组合风险：** 检查罕见事实组合、精确日期与金额、财产线索、法院与地域信息、附件和文件元数据；能推断出案件或身份的，进一步泛化或删除。
4. **映射表不外发。** 代号与真实信息的映射只存本机私有目录。

代号替换**不等于**匿名化；脱敏包仍可能含个人信息。

### 6.3 外发准入记录（私有）

每次外发前，由所有者确认并记录：

- 允许发送的字段清单；
- 接收方、处理边界、是否保留输入、是否用于训练、是否再共享、处理地域；
- 审计责任人。

任何一项无法确认，即不传输。能否向第三方披露真实材料，由所有者依保密义务和个人信息保护规则另行判断；本设计不预设任何许可，也不以委托人知情、供应商国籍或仓库记录代替该判断。

### 6.4 可核验范围

| 清单项 | 脱敏视图下模型能核验的范围 | 必须由复核人用原件核验的部分 |
| --- | --- | --- |
| C1 案件一致 | 包内结构是否只指向一个案件代号 | 真实案件身份、是否混入其他案件 |
| C2 材料登记 | 引用是否都有登记代号 | SHA-256 与原件一致、证据矩阵状态 |
| C3 事实出处 | 每条事实是否标了出处 | 出处是否真实支持该事实 |
| C4 依据时效 | 是否引用了时效包、核对日期是否写明 | 依据是否仍有效 |
| C5 期限 | 期限是否被列出、相对顺序是否合理 | **真实日期和是否届满**（脱敏后模型通常无法判断） |
| C6 禁止类别 | 内容是否落入禁止类别 | — （复核人仍须复核） |
| C7 法律结论 | 是否给出结论、意见或行动建议 | — （复核人仍须复核） |
| C8 强制提示 | 四项提示是否齐全、未改动 | — |
| C9 冲突局限 | 是否列明 | 是否有原件中可见而未列出的冲突 |
| C10 个人信息 | 脱敏包内是否残留 | 原包的最少化 |
| C11 SHA 一致 | 脱敏包自身 SHA | **原包输入输出 SHA**（模型无法核验） |

模型在脱敏视图下的"通过"只表示"在可核验范围内未发现问题"，不得记为原件通过。

### 6.5 留痕

原复核包、脱敏包、交叉检查结果各自计算 SHA-256，在私有记录中相互绑定。公开仓库不记录任何一项。

## 七、委托人沟通凭证（对应 B-05）

1. **C03 之外。** 和解、拍卖、移送公安、恢复执行等委托人决定，仍按 R2 §八 排除在 C03 之外。律师以独立核验的事实和自己的专业判断，在 C03 之外履行说明和沟通义务。
2. **不转发。** 候选、复核包和 AI 意见一律不转发给委托人，不作为给委托人的意见、指示或授权。
3. **两类凭证分开：**
   - **已告知：** 律师已就某事项向委托人说明；
   - **已取得明确指示：** 委托人已就某事项作出决定。
   每一项拟采取的下一步须事先声明需要哪一类凭证、由谁核实。
4. **缺失或撤回即阻断。** 需要的凭证缺失、过期或被撤回的，阻断。
5. **地位有限。** 凭证只是外侧的私有记录；不能替代保密审查、第三方披露许可，也不能替代 AR-B-010 的逐项决定。委托人的指示针对委托人自己的决定，不是对候选内容的背书。
6. **公开仓库不记录。** 沿用 R2 §九 的最小留痕；不按候选公开凭证，也不写"已附"。

## 八、复核与放行的两个受控事件（适用于 L2；对应 B-04）

### 8.1 事件

- **事件 R（复核处置）** 与 **事件P（放行复确认）** 分别形成记录，各自绑定：候选代号、版本、输出 SHA-256、复核包 SHA-256、定级记录 SHA-256、处置原文、拟授权的下一步。
- 每个事件的时间须在**当时**由外侧受控方式记录（例如当时生成并签署的记录，或可信时间来源）。禁止事后补填时间。

### 8.2 顺序与间隔

1. 交叉检查结果时间 < 事件 R 时间 < 事件 P 时间。
2. 事件 P 时间 − 事件 R 时间 ≥ 24 小时。
3. 事件 P 时间在处置有效期之内；有效期按 R2 §五 C4、C5 计算，截止点**不含**届满的那一刻。

### 8.3 重新计时

依据、期限、复核包、用途、撤回状态或资格声明状态任一发生变化，原事件 R 失效；复核重做后，从新的事件 R 重新计时，不得沿用旧起点。

### 8.4 阻断

- 时间来源、可信度或先后顺序无法确认的，阻断。
- 期限紧迫**不是**缩短 24 小时的理由，也不是由系统自动改走替代路径的理由。期限风险由律师在 C03 之外处理。

### 8.5 诚实说明

在外侧可信时间和留痕能力建立之前，纯函数只能检查输入中的时间是否满足上述约束，**不能证明**律师真的等待了 24 小时。同一律师的两次事件也不等于两名独立复核人。

## 九、代码强制（V8 拟实现范围；对应 B-06）

V8 另行实现、审查、正式运行。本节只定义合同。

### 9.1 纯函数边界

所有检查都是纯函数：当前时间由调用方传入；函数本身不读时钟、不做输入输出、不持久化。

### 9.2 封闭输入记录

函数只接受一份封闭的输入记录，字段固定，不接受多余字段：

| 组 | 字段 |
| --- | --- |
| 候选绑定 | 案件代号、候选代号、版本、输入集 SHA-256、输出 SHA-256、输出类别 |
| 用途绑定 | 用途、受众、拟采取的下一步 |
| 版本 | 设计版本 `R3`、清单版本 `CL-005-R2` |
| 复核包 | 复核包 SHA-256 |
| 定级 | 级别、定级记录 SHA-256、定级人代号 |
| 处置 | 处置原文（4 种之一）、C1–C11 各项结果、重大冲突状态、撤回／取代状态 |
| 复核人 | 复核人代号、资格声明引用、独立性声明引用、声明状态 |
| L2 附加 | 交叉检查记录（§五 5.2 的绑定字段）、各项意见及分歧处理、外发准入记录引用、事件 R 与事件 P、所需委托人凭证的类别、引用和状态 |
| 外侧状态 | 时间可信标记、撤回传播状态、防重放标识 |
| 调用参数 | 当前时间 |

### 9.3 校验规则

1. 所有绑定字段在各子记录之间必须一致；任何一处不一致即阻断。
2. 处置必须是 R2 §七 的 4 种原文之一；只有 APPROVE 才可能得到正面结果。
3. C1–C11 必须全部为"通过"。
4. 重大冲突状态必须为"无"；撤回／取代状态必须为"无"。
5. 复核人代号已登记、不是生成者；资格与独立性声明引用存在且状态为有效。
6. 定级符合 §三：L1 须有正面确认且用途在封闭清单内；其他一律按 L2。
7. L2 另须满足：§五 停点全部解除；§六 外发准入记录存在；§八 顺序、间隔、有效期全部满足；拟采取的下一步需要的委托人凭证存在且有效。
8. 外侧状态中，时间不可信、撤回未传播或有重放迹象的，阻断。

### 9.4 输出

- **阻断**：附理由码，指明哪一条不满足。理由码为封闭集合，例如 `BINDING_MISMATCH`、`DISPOSITION_NOT_APPROVE`、`CHECKLIST_NOT_ALL_PASS`、`MATERIAL_CONFLICT_OPEN`、`WITHDRAWN_OR_SUPERSEDED`、`REVIEWER_INVALID`、`TIER_INVALID`、`L1_NOT_POSITIVELY_CONFIRMED`、`CROSS_CHECK_STOP_UNRESOLVED`、`EGRESS_NOT_ADMITTED`、`EVENT_ORDER_INVALID`、`COOLING_PERIOD_UNMET`、`VALIDITY_EXPIRED`、`CLIENT_RECORD_MISSING`、`EXTERNAL_STATE_UNTRUSTED`。
- **最大正面结果**：`ELIGIBLE_TO_REQUEST_AR_B_010`，即"可以另行申请 AR-B-010 的逐项授权"。该结果不是授权，不执行任何动作，不解锁下游；下游始终阻断，直至 AR-B-010 的逐项决定。

### 9.5 外侧责任（代码不能做的）

资格是否真实、外部记录如何取得、脱敏是否充分、时钟是否可信、留痕、跨次调用防重放、撤回如何传播，都由代码之外负责，并以可核验的输入交给函数。外侧没有可信状态时，函数不能给出正面结果。

### 9.6 与现有代码的关系

现有 `isolation.py` 只限制处置原文和类别，保持候选待人工复核、下游阻断；`contracts.py` 的候选记录不是人审、时钟或放行记录；`isolation.py` 的字段与值筛查也不是匿名化检测。这些现有保护**不能**当作本节已经实现的证据。

## 十、事后抽查（对应 NB1）

1. **范围：** 每个自然季度（按北京时间）内作出处置的候选。同一候选的多个版本，只计最后一个作出处置的版本。
2. **数量：** 抽取数 = 向上取整（该季度候选数 × 10%），且不少于 2；不足 2 份的全部抽查。
3. **优先：** 先从 L2 中抽取；L2 不够再从 L1 抽取。
4. **选样方法：** 按候选代号排序，用一个公开、可复算的方法选样（例如以季度末日期串的 SHA-256 作为种子取模）。种子和选样结果写入私有记录。
5. **抽查者：** 跨模型交叉检查（只看经 §六 准入的脱敏包），或经所有者另行同意的同行律师。
6. **结果：** 只用于改进。尚未执行的事项仍按 R2 §十 处理撤回；已执行的事项不自动改写历史，也不自动改变既有决定，发现问题时另行评估。发现系统性问题的，须修订本设计。

## 十一、仍然存在的局限

R2 采纳决定所列的局限**全部保留**：复核人身份与资格是本人声明；独立性只是部分独立；复核人参与了输入的准备。此外：

1. 复核与放行的最终决定权仍在一人。R3 只是**拟缓解**，没有消除集中。在 V8 实现并正式运行、外侧控制有证据之前，记录时一律写"拟缓解，未验证"，不写"已缓解"或"已解决"。
2. 同一律师的两个时点不等于两名独立复核人。
3. 交叉检查只看脱敏材料，可能漏掉只有原件才能看出的问题；跨模型检查与生成模型也可能犯同样的错。
4. 代码只检查记录是否齐全、是否一致，不检查判断本身是否正确。
5. 外侧可信时间、留痕、防重放和撤回传播目前都尚未建立，也未核验。
6. 此前各轮均为同模型审查；本稿不改写这一历史。
