## 一、范围、目的与总原则

### 1.1 拆分

按所有者 2026-11-09 的选择，本设计拆为两部分：

| 部分 | 内容 | 所在 |
| --- | --- | --- |
| **R3（本文件）** | 由复核人本人执行、靠书面记录留痕的程序规则 | 本文件 |
| **V8 代码强制** | 签名、可信时间、防重放、信任根、封闭输入合同、理由码 | 另行设计，代号 `C03-GATE-ENFORCEMENT-V8`。本文件第十节只列出已知的要求，不定义合同 |

R3 的规则在 V8 实现之前就可以由人执行；V8 实现之后，由代码对其中能机械检查的部分加以强制。R2 采纳时已有的代码保护（处置原文检查、候选保持待人工复核、下游始终阻断）继续有效，不因拆分而取消；本文件所说"没有代码强制"，只指 R3 **新增**的控制。修订三的 §十（代码强制）和 §十一（外侧交接合同）不再属于 R3，只作为 V8 设计的输入材料。

### 1.2 目的

R2 留下了一项局限：复核和放行集中在一人身上。在只有一名执业律师的前提下，这项局限无法消除。R3 的目标是**降低**一人判断出错的概率，并让错误更容易被发现。

### 1.3 总原则（以下各节都不得违反）

1. **AI 永远不是复核人。** 复核人只能是合格执业律师，处置只能由人作出。任何模型的意见都只是参考。
2. **R2 是底线。** R3 只增加控制，不放宽 R2 的任何要求。R3 与 R2 冲突时，按更严格的一方执行。
3. **L2 只是额外保护标签。** L2 不扩大 C03 的允许输出、允许用途或受众。R2 §八（升级边界）排除的事项，在 R3 下仍然排除；R2 禁止的用途不是"L2 路径"，AR-B-010 也不能推翻这些禁止。
4. **不确定即阻断。** 任何定级、证据、时间、绑定或外部状态无法确认的，一律阻断，不退回到更宽松的路径。
5. **最大正面结果只有一个：** 可以另行申请 AR-B-010 的逐项授权。R3 的任何控制都不构成授权、执行或解锁。

### 3.2 R2 §六 各字段的归属与形成时点

| R2 §六 类别 | 承载记录 | 形成时点 |
| --- | --- | --- |
| 候选身份（代号、版本、输出 SHA-256、生成时间、类别、能力引用与操作类型） | M | 复核开始前 |
| 案件与目的：案件代号与版本 | M | 复核开始前 |
| 案件与目的：具体用途 | T（用途代号） | M 之后、复核开始前 |
| 追溯引用（输入材料代号与 SHA-256、契约与映射、遗漏／冲突／不利情况、失败与审计记录） | M | 复核开始前 |
| 依据（时效包条目、核对日期） | M | 复核开始前；放行时的重查记在 P |
| 已知局限与禁止用途 | M | 复核开始前 |
| 设计版本（设计代号、版本、正文 SHA-256；清单版本） | M | 复核开始前 |
| 复核范围：**拟审范围** | M | 复核开始前 |
| 复核人：代号、资格参考代号（已存在的引用） | M | 复核开始前 |
| 撤回状态 | R（复核时的状态）、P（放行时的状态）、Q（申请时的状态） | 各自形成时 |
| 复核范围：**实际审查范围** | R | 复核时 |
| 复核人：当次资格与独立性声明（R2 E-006 六项） | I | **实质审查开始前**；R 只引用 I |
| 结果（清单勾选、处置、理由、日期、有效期） | R | 复核时 |

M 不含任何只有复核之后才能形成的内容。缺少任何一项，或者归属错位（例如在 M 里预填处置），复核关口即阻断。

**I 的要求：** I 在复核人开始实质审查（定级 T 和清单 C1–C11 审查）之前形成，引用 M，逐项写明 R2 §四 的六项声明，并写明形成时间。任何一项不能声明、未签署、形成时间晚于 T，或者事后补签，复核关口即阻断。资格、独立性或输入参与情况发生变化的，I 和其后的全部记录失效。

### 3.3 单向引用顺序

```text
L1：M → I → T → R → Q
L2：M → I → T → E → S → X →（如有）V → R → P → Q
```

- 每份记录写明它所引用的前件的 SHA-256；不把自身的摘要写进自身。
- V 引用 M、T 和它所针对的那一份 X；R 引用 I 和它所依据的全部 X 和 V。
- R 所依据的 X，必须在 R 形成**之前**取得并在 R 中引用。R 之后才取得的 X 不能回填为 R 的依据；如要使用，须形成新的 R（L2 还须新的 P），从新的 R 重新计时。
- **重做的起点是最早失效的那份记录**，其后的记录一律重做，不能只补写 R。
- 把已经被引用的记录归档，不改变任何记录。
- M 改变（换包）时，引用旧 M 的全部记录失效，须从新的 I 开始重做。
- M 未变而 I 或 T 失效时，E、S、X 随之失效。同一 M 不能再次送检（§6.5 第 1 项），因此该 M 的 L2 流程保持阻断；只能通过 C03 生成新候选（新的 M）重新开始。

### 3.4 哈希规则

- 材料文件：对原始字节计算 SHA-256。
- 记录：JSON 对象。解析时拒绝重复键和非法 JSON；按 RFC 8785（JCS）规范化后的 UTF-8 字节计算 SHA-256。
- SHA-256 一律写为 64 位大写十六进制。

### 3.5 设计版本绑定

M 写明：设计代号 `C03-GATE-DESIGN-005`、**被采纳的 R3 正文 SHA-256**、清单版本 `CL-005-R2`。各修订稿的正文 SHA 不同，不能混用。

## 四、风险定级与允许用途（对应 B-01、F-04、N-01）

### 4.1 级别

| 级别 | 定义 |
| --- | --- |
| L1 内部底稿 | 只供复核人本人内部整理；不影响任何对外文书或委托人决策 |
| L2 受控底稿 | 复核人本人在 C03 之外自行起草文书或准备沟通时，作为内部参考 |

两级的**受众都只能是复核人本人**。候选在任何级别下都不得对外发送、转发、作附件或原样进入对外文书。

### 4.2 允许用途表（封闭）

只有下表所列组合是允许的。表外组合一律直接拒绝，不按 L2 处理。

| 用途代号 | 级别 | 允许的输出类别（WP-007 §16.1） | 受众 | 拟采取的下一步 | C03 内部关口所需委托人凭证 |
| --- | --- | --- | --- | --- | --- |
| U1 内部整理 | L1 | 全部 5 类 | 复核人本人 | 内部存档、整理（事实梳理、期限表、材料清单、冲突清单） | 不收集 |
| U2 起草参考 | L2 | `ISSUE_MATRIX`、`ADVERSE_CONDITION_REGISTER`、`CONFLICT_AND_INFORMATION_GAP_REGISTER`、`AUTHORITY_CHECK_REQUEST` | 复核人本人 | 复核人在 C03 之外**自行**起草文书；候选不原样进入、不作附件 | 不收集 |
| U3 沟通准备参考 | L2 | 同 U2 | 复核人本人 | 复核人在 C03 之外**自行**与委托人沟通；候选不转发 | 不收集 |

说明：

- **级别由用途代号派生**（U1 → L1；U2、U3 → L2），不另行填写。
- 允许用途表只能通过修订本设计来增改，不能由单份记录填写或临时开通。
- "不收集"只是说：C03 的这一内部关口不办理委托人取舍或对外动作，因此不收集委托人凭证。它**不决定** C03 之外的事项是否需要委托人指示。U3 涉及的说明义务、委托权限、委托人指示和保密判断，仍由律师在 C03 之外依法处理，不因此豁免。
- 枚举表不能替代复核人对内容实质的审查：C6（禁止类别）、C7（法律结论）仍由复核人逐项判断。例如一份"方案比较"如果实质上是执行策略，属于 WP-007 §16.2 的禁止类别，应在生成和复核环节阻断。
- U2、U3 不构成 C03 对外发送或进行法律行为的授权。

### 4.3 定级记录 T

- 由复核人形成，引用 M 的 SHA-256，写明用途代号、输出类别、受众、下一步。
- L1 须复核人**正面确认**用途为 U1；不存在默认的 L1。

### 4.4 拒绝与重定级

按下列顺序判断，先命中的优先：

| 顺序 | 情形 | 处理 |
| --- | --- | --- |
| 1 | 用途中**已知**含禁止目的（例如对外附件、转发委托人），或已确定的组合不在允许用途表内 | 直接拒绝，不按 L2 处理 |
| 2 | T 缺失，或字段互相矛盾 | 阻断，须重新形成 T |
| 3 | 用途尚未确定、未核实、混合或冲突（但不含已知的禁止目的） | 保持阻断。只有复核人核实后建立**唯一一个**落入 U1、U2 或 U3 的组合，并重新形成 T，才可继续 |

用途漂移是独立规则，与上表无关：用途、受众、下一步、来源或范围发生实质变化，原 T 及其后全部记录失效，须重新定级、重新复核；新用途落入哪一行，都不能保住旧链。

## 六、跨模型交叉检查与停点（适用于 L2；对应 B-02、NB-02、G-04）

### 6.1 地位

- 执行者是另一家公司的模型，目前指定为 Codex；不得使用与生成者同一模型家族的模型。
- 交叉检查**只提供意见**：不作处置，不是复核人，不构成授权。"通过"不能替代复核人对 C1–C11 的逐项核验。

### 6.2 最低覆盖（固定）

- 每份 X 必须对 **C1–C11 全部 11 项**逐项给出意见。覆盖范围由本设计固定，不能由报告或调用方缩减。缺任何一项，X 即视为未完成，L2 阻断。
- 每项意见只能是：`通过`、`不通过`、`无法判断-可见范围内`、`无法判断-脱敏盲区`。
- **脱敏盲区只适用于下表所列的子判断。** 每项的"可见部分"仍必须给出 `通过`、`不通过` 或 `无法判断-可见范围内`，不能整项标为盲区。

| 清单项 | 可见部分（必须判断） | 脱敏盲区（只限这些子判断） |
| --- | --- | --- |
| C1 案件一致 | 包内是否只指向一个案件代号 | 真实案件身份、是否混入其他案件 |
| C2 材料登记 | 引用是否都有登记代号 | SHA-256 与原件一致、证据矩阵状态 |
| C3 事实出处 | 每条事实是否标了出处 | 出处是否真实支持该事实 |
| C4 依据时效 | 是否引用了时效包、核对日期是否写明 | 依据是否仍有效 |
| C5 期限 | 期限是否被列出、相对先后是否合理、是否标明状态 | 真实日期和是否届满 |
| C6 禁止类别 | **整项可见**，不得标为盲区 | — |
| C7 法律结论 | **整项可见**，不得标为盲区 | — |
| C8 强制提示 | **整项可见**，不得标为盲区 | — |
| C9 冲突局限 | 是否列明 | 原件中可见而未列出的冲突 |
| C10 个人信息 | 脱敏包内是否残留 | 原包的最少化 |
| C11 SHA 一致 | 模型对所见精确字节的复算 | 原包输入输出 SHA |

### 6.3 停点

底线：R2 §五 要求 C1–C11 全部通过才可能 APPROVE；R2 §十 要求未解决的重大冲突即阻断。

| 意见 | 适用 | 处理 |
| --- | --- | --- |
| `不通过` 或 `无法判断-可见范围内` | C5 可见部分、C6、C7 | **硬停点** |
| `不通过` 或 `无法判断-可见范围内` | 其他各项的可见部分 | 停点 |
| `无法判断-脱敏盲区` | §6.2 表所列子判断 | 必须形成盲区 V（§6.4）。该子判断**没有独立检查**，记为"复核人原件核验，无外部交叉检查"，不得记为"外审通过" |
| 缺项、取值不合法、盲区用在表外、结果互相矛盾、绑定不符 | 任一项 | X 未完成，L2 阻断 |

以下做法都不构成解除：写异议说明、重复确认、等待 24 小时、在放行时点重新确认。

### 6.4 解除记录 V

V 绑定：M、T、它所针对的**那一份 X** 的 SHA-256；具体清单项和具体争点（子判断）；解除类型；证据引用。解除类型只有两种：

| 类型 | 用途 | 证据要求 |
| --- | --- | --- |
| `MODEL_FINDING_REFUTED_BY_ORIGINAL` | 停点：证明模型的意见是误报 | 逐条列出材料登记代号、SHA-256、页码或行号；每个 SHA-256 必须出现在 M 的追溯引用中 |
| `ORIGINAL_VERIFICATION_OF_BLIND_SCOPE` | 盲区：复核人对原件核验该子判断 | 同上 |

不允许用"是／否"或一句"已解除"代替 V。

**当轮解除：** 停点出现在本 M 的 X 中时，可以在**同一个 M** 上，以绑定该 X 的 V（`MODEL_FINDING_REFUTED_BY_ORIGINAL`）直接解除，不必重新生成。跨版本、跨系列延续下来的旧停点，以及解除的适用范围，按 §6.5 处理。

### 6.5 防止挑选结果（对应 NB-02、G-04、H-03）

1. **一份 M 只能有一份 X。** 同一 M 的脱敏包只能发送一次。只改脱敏代号、格式、空格或措辞而得到的不同脱敏包，属于**等效重送**，禁止。
2. **停点索引 H（私有，L1、L2 都适用）。** H 只追加事件，不覆写历史。事件有两种：

   **发现事件**（每出现一个停点登记一条）：

   | 字段 | 模型停点 | 人工停点 |
   | --- | --- | --- |
   | 来源 | X 判出 | 复核人自己发现（包括决定不送检的情形） |
   | 案件代号、清单项、争点简述 | 必填 | 必填 |
   | 所在候选（代号、版本）与 M 的 SHA-256 | 必填 | 必填 |
   | X 的 SHA-256 | 必填 | 写"不适用" |
   | 发现阶段 | — | M 之后、T 时、E 之前、R 时（择一） |
   | 原件定位 | 可选 | 必填（材料登记代号、SHA-256、页码或行号） |
   | 私有发现记录的 SHA-256 | — | 必填 |
   | 登记时间 | 必填 | 必填 |

   **解除事件**（引用发现事件），类型只有两种，适用范围不同：

   | 解除类型 | 含义 | 适用范围 | 证据 |
   | --- | --- | --- | --- |
   | `FINDING_REFUTED` | 原发现本身是错的（模型误报，或复核人的人工发现有误） | 该案件中该争点的**全部**候选 | V（`MODEL_FINDING_REFUTED_BY_ORIGINAL`），或对人工停点的原件核验记录；逐条原件定位 |
   | `CORRECTED_IN_CANDIDATE` | 原发现成立，只是在某一份候选中已实质修正 | **只限**写明的那一份候选（代号、版本、M 的 SHA-256） | T 中的实质修正说明及修改前后对照；L2 另须本候选 X 对该项 `通过`；L1 须复核人在 R 中对该项重新审查通过 |

3. **查询（前置）。** 复核人在下列时点按**案件代号**查询 H 的**全部**发现事件（不只是"未解除"的），并把查询结果的 SHA-256 写入相应记录：
   - L1：形成 R 之前，写入 R；
   - L2：形成 E 之前，写入 T。

   对每一个发现事件，逐条写明：与本候选是否实质相关、理由；如相关，是否已有一个**适用范围覆盖本候选**的解除事件。只有 `FINDING_REFUTED`，或者针对本候选本身的 `CORRECTED_IN_CANDIDATE`，才算覆盖本候选。针对其他候选的 `CORRECTED_IN_CANDIDATE` 不覆盖本候选。

   查询之后、发送之前（L2）或 R 之前（L1）又出现新的相关停点的，重新查询；来不及重新查询的，停止。

4. **编号不清除停点。** 候选代号、系列代号、输出类别或用途改变，都不能自动清除相关停点。是否实质相关，看候选内容是否涉及同一争点（例如同一期限、同一事实、同一依据），不看编号。相关性或历史不明的，按相关处理；仍无法判断的，阻断。

5. **未被覆盖的相关停点。** 每一个相关、但没有覆盖本候选的解除事件的停点，只能通过下列方式之一解除，才可继续：
   - 证明原发现是错的：形成 `FINDING_REFUTED` 解除事件（模型停点用 V，V 须定位到旧停点所在的那一份 X 和那一个争点；人工停点用原件核验记录）；或者
   - 在本候选中实质修正：在 T 中写明修正及修改前后对照；L2 在本候选的 X 对该项给出 `通过` 后、R 之前，L1 在 R 中对该项重新审查通过时，形成针对本候选的 `CORRECTED_IN_CANDIDATE` 解除事件。解除事件形成之前，不得作出 APPROVE。
   没有实质修正的重新生成，不能解除旧停点，本候选阻断。

6. 每一版的 X 和停点都保留在私有记录中，不得删除。
7. 脱敏盲区导致部分子判断无法独立检查，是**可用性局限**，不是放宽停点的理由。

## 七、外发准入与发送（适用于 L2；对应 B-03、F-03、G-03）

### 7.1 关口在前

脱敏包交给任何第三方模型之前，须先形成 E，并按 §7.4 在发送前核对。**不通过即不发送**；L2 继续阻断，不回退到未脱敏外发，也不回退到 L1。

### 7.2 本地准备

1. **最小化：** 只保留交叉检查所需的结构和内容。
2. **直接标识：** 人名、名称、证件号、账号、地址、电话、案号一律用代号替代。
3. **间接标识与组合风险：** 检查罕见事实组合、精确日期与金额、财产线索、法院与地域信息、附件和文件元数据；能推断出案件或身份的，进一步泛化或删除。
4. **映射表不外发。** 代号与真实信息的映射只存本机私有目录。

代号替换**不等于**匿名化；脱敏包仍可能含个人信息。

### 7.3 外发准入记录 E（私有）

由所有者形成，引用 M、T 的 SHA-256，并写明：

- 脱敏包 D 的**精确字节** SHA-256；
- **完整外发范围**：除 D 之外，本次调用还会带出的全部内容（例如系统提示、任务说明、会话历史、附带文件）。默认要求在全新会话中只发送 D 和固定的任务说明；任务说明的 SHA-256 也写入 E；
- 允许发送的字段清单；
- 接收端：提供方、模型标识、调用入口或账户代号；
- 处理条件，须**逐项明确接受**：输入保留期限、是否用于训练、是否再共享、处理地域；以及据以判断这些条件的**配置依据**（账户设置、服务条款或接口参数的版本或截图，及其 SHA-256）。"能确认会保留"不等于"已接受保留"；未逐项明确接受的，不发送；
- 有效窗口（起止时间）与撤回状态。

能否向第三方披露真实材料，由所有者依保密义务和个人信息保护规则另行判断；本设计不预设任何许可，也不以委托人知情、供应商国籍或仓库记录代替该判断。

### 7.4 发送前核对与发送记录 S

发送前，所有者逐项核对，全部相符才发送：

1. 实际要发出的字节的 SHA-256 与 E 中 D 的 SHA-256 相同；固定任务说明的 SHA-256 与 E 中记录的相同；D 中的字段只在 E 的允许字段清单之内；
2. 实际外发范围与 E 中的完整外发范围相同：无多余上下文或附件。全新会话只是必要条件，不能单独作为隔离的证据；对接收端是否会带入隐含上下文（例如记忆、项目文件、默认指令）也须当场核对；
3. 实际接收端与 E 相同；
4. **本次调用实际生效的处理条件**与 E 逐项相同：当场重新查看账户设置、条款版本或接口参数，留存当场的配置证据；
5. 当前时间在 E 的有效窗口之内，E 未撤回。

隐含上下文、模型来源或实际生效设置中任何一项无法确认的，不发送；已经收到的 X 如对应的发送无法确认符合 E，不接收为 R 的依据。

发送后形成 S，写明：E 的 SHA-256、实际发出字节的 SHA-256、实际外发范围、实际接收端、当场配置证据及其 SHA-256、核对结果、请求标识（如接收端提供）、发送时间。

### 7.5 时序

E 形成时间 < S 发送时间；S 发送时间在 E 的有效窗口之内；X 收件时间 ≥ S 发送时间；X 必须对应同一次发送（同一请求标识，或同一会话的回复）。

### 7.6 不合规发送

核对后发现已发送的内容、范围、接收端或处理条件与 E 不符的：

- 不能靠补签 S 或事后检查补救；
- 立即停止，记入私有记录，由所有者依保密义务另行决定补救措施；
- 该 M 的 L2 流程阻断。

### 7.7 C11 的三种证据

只有第三种能满足 C11：

1. 模型**看到了**某个摘要值；
2. 模型对其**所见的精确字节**独立复算了摘要（只证明 D 的一致性）；
3. 复核人对**原包**核验了输入输出 SHA-256，并在 R 中记录。

### 7.8 留痕

M、T、D、E、S、X、V 各自计算 SHA-256，在私有记录中相互绑定。公开仓库不记录任何一项。

## 八、委托人沟通凭证（对应 B-05、F-04）

1. **C03 之外。** 和解、拍卖、移送公安、恢复执行等委托人决定，仍按 R2 §八 排除在 C03 之外。复核人以独立核验的事实和自己的专业判断，在 C03 之外履行说明和沟通义务。
2. **不转发。** 候选、复核包和 AI 意见一律不转发给委托人，不作为给委托人的意见、指示或授权。
3. **两类凭证分开：** "已告知"（律师已就某事项向委托人说明）与"已取得明确指示"（委托人已就某事项作出决定）。
4. **需要哪一类由设计决定。** 只由 §4.2 允许用途表的最后一列决定。目前三种用途都"不收集"。今后新增需要凭证的用途，须独立修订、复核、采纳本设计，不能临时开通。
5. **凭证 K 的绑定（供今后使用）。** K 绑定：事项（案件代号）、所覆盖的具体动作、范围、类别、核实人、形成时间、有效状态。K 不得跨动作复用。
6. **地位有限。** K 只是私有记录；不能替代保密审查、第三方披露许可，也不能替代 AR-B-010 的逐项决定。
7. **公开仓库不记录。** 沿用 R2 §九 的最小留痕；不按候选公开凭证，也不写"已附"。

## 九、有效期与受控事件（对应 B-04、F-02、G-02 的程序部分）

### 9.1 时间的格式与形成

- 所有时间一律为带明确时区偏移的 ISO 8601 时间，按真实日历解析；没有时区偏移、日期不存在或无法解析的，阻断。
- 只有日期的期限，按北京时间（+08:00）该日 00:00 计（偏早，偏安全）。
- 每份记录都在**当时**形成，并写明形成时间。禁止事后补填。
- 在 V8 建立可信时间之前，时间的真实性只靠复核人当时记录，这是局限（第十三节）。

### 9.2 有效截止（两级都适用）

有效截止 = 下列各项中**最早**的一个：

1. 依据时效包的核对日期（北京时间）后第 30 日的 00:00（+08:00）；
2. C5 所列每一项**适用**期限的届满时刻。

C5 的每一项期限须标明状态：`适用`（给出届满时刻）、`无适用期限`（须复核人在 R 中正面声明）、`未知`。任何一项为 `未知` 的，阻断。没有任何期限时，须在 R 中正面声明"无适用期限"，不能留空。

截止**不含**届满的那一刻。

### 9.3 复核事件 R（L1、L2）

引用 M、I、T 及（L2 时）全部 X、V；写明处置原文、C1–C11 各项结果、实际审查范围、重大冲突状态、撤回状态、C11 的原包核验、C5 期限清单与各项状态、有效截止、形成时间。

### 9.4 放行事件 P（仅 L2）

- 引用 R。
- 复核人须**正面重核**并逐项记录（不是"未发现变化"，而是"已重查"）：
  1. 复核结论仍然成立；
  2. C5 所列期限已逐项重查，没有变化（逐项列出重查结果）；
  3. 依据仍然有效：附一份依据重查记录，其形成时间**晚于 R 的形成时间**（不以"同一天"代替）；
  4. 撤回状态：已重查，无撤回。

### 9.5 时间条件

| 条件 | L1 | L2 |
| --- | --- | --- |
| R 的形成时间 < 有效截止 | 必须 | 必须 |
| 每份 X 的收件时间 < R 的形成时间 | — | 必须 |
| P − R ≥ 24 小时 | — | 必须 |
| P 的形成时间 < 有效截止 | — | 必须 |
| P 含 §9.4 四项正面重核 | — | 必须 |

### 9.6 对照复查 Q（L1、L2；对应 H-02）

R（L1）或 P（L2）只说明当时成立。以下三个时点，复核人都须当时形成一份新的 Q。三份 Q 按顺序追加，不替换原申请链：

| Q | 时点 | 引用 | 额外要求 |
| --- | --- | --- | --- |
| Q1 | 提交 AR-B-010 申请之前 | R（L2 还引用 P）；拟提交的申请内容 | Q1 通过后才提交申请；申请引用 Q1 |
| Q2 | 所有者作出授权决定之前 | 待决的申请（含 Q1） | Q2 通过后，所有者才作出逐项决定；决定绑定申请链与 Q2 |
| Q3 | 实际使用候选之前 | 已作出的确切授权 | 见下文"授权自身" |

每份 Q 以原件和当前状态**逐项对照** R/P，留存对照表：

| 对照项 | 要求 |
| --- | --- |
| C5 每一项期限 | 适用性、具体届满时刻与 R/P 所记**完全相同**；没有改期、提前或推后 |
| 新出现的期限 | 无 |
| 已届满的期限 | 无 |
| 有效截止 | 按当前状态重新计算，与 R/P 相同，且 `Q 的形成时间 < 有效截止` |
| 依据 | 仍然有效，没有修改或废止 |
| 复核人资格与独立性 | 与 I 相同，没有变化 |
| 撤回状态 | 候选、M 中材料、依据均未撤回 |

Q3 另须**正面核验授权自身**：

| 对照项 | 要求 |
| --- | --- |
| 授权是否存在 | 存在，且绑定的正是本条记录链（候选、M、申请、Q2） |
| 授权撤回状态 | 未撤回 |
| 授权自身期限 | 未过授权写明的截止时间（如有）；且仍早于记录链的有效截止 |
| 授权次数 | 未用尽（如授权限定次数） |
| 动作与范围 | 拟采取的动作和范围与授权写明的**完全相同** |

任何一项有变化或无法确认，**停止**，不得申请、授权或使用。记录链本身失效的，从最早失效的记录重做（§3.3）；授权缺失或失效的，须重新申请。新的 Q 不能代替缺失或失效的授权。

每份 Q 只证明它形成那一刻成立。之前形成的 Q 不能用于之后的时点；已批准的旧链在后续时点发现失效，也应停止，不得继续使用。Q 是追加的核对记录，不改变申请或授权所绑定的标的。

### 9.7 重新计时

依据、期限、M、用途、撤回状态或资格声明状态任一发生变化，原 R 失效；从最早失效的记录重做（§3.3），再从新的 R 重新计时，不得沿用旧起点。

### 9.8 期限紧迫

期限紧迫**不是**缩短 24 小时的理由，也不是改走替代路径的理由。期限风险由律师在 C03 之外处理。

## 十、V8 代码强制：移交事项（对应 B-06、F-05、G-02、G-05）

V8 另行设计（`C03-GATE-ENFORCEMENT-V8`），另行交跨模型复核和所有者采纳。在 V8 采纳并正式运行之前，R3 的全部规则只靠复核人执行，**没有任何代码强制**。

V8 设计至少要解决以下已知问题（来源：Codex 第二、三轮）：

1. **可信时间与调用新鲜度（G-02）：** 区分事件发生时间与本次调用的新鲜度；用挑战值或等效机制把时间与本次调用绑定；旧时间戳不能作为本次调用的当前时间；状态快照须满足 `R/P < 快照时间 ≤ 当前时间 < 有效截止`，并覆盖整条证据链。
2. **信任根与签名（G-05）：** 由受控入口固定信任的公钥、算法、角色与状态，不接受调用方自带的登记表；规定每类记录的规范化载荷、签名覆盖和摘要覆盖。
3. **封闭输入合同：** 完整记录或经外侧核验并明确绑定的证明，不接受无证据的布尔值。
4. **模型来源核验（A-32）：** 取得可验证的提供方与模型家族，不信任手填标签。
5. **理由码与优先级（N-01）：** 唯一的优先级或有序多理由输出；区分前件引用断裂与前件实体不符，区分模型来源未知与已确认同家族。
6. **AR-B-010 精确绑定（G-05）：** 下游独立核对同一候选、M、完整记录链、事项、目的、动作、范围、有效期与撤回状态；最终执行和一次性使用登记在外侧。
7. **最大正面结果**仍只能是"可以另行申请 AR-B-010"。

修订三 §十、§十一 的文本（见 git 历史）作为 V8 设计的起点材料，不随 R3 采纳。

V8 设计还须从最终采纳的 R3 继承以下人工程序义务，并写明哪些只能由人或外侧完成：I（复核前声明）、Q（三个时点的对照复查）、E/S 的当场配置核对、等效重送禁止、停点索引 H 与前置查询。这些义务不因 V8 建成而转移给代码。

## 十一、AR-B-010 申请的绑定（程序部分；对应 G-05）

R3 下的最大正面结果，是复核人可以另行申请 AR-B-010。申请须写明并引用：

- 确切的候选（代号、版本、输出 SHA-256）、M、I、T 及完整记录链（L1：R、Q；L2：E、S、X、V、R、P、Q）；
- 事项（案件代号）、用途代号、拟采取的那一个动作、范围、有效截止；
- Q1。

授权前须形成 Q2，实际使用前须形成 Q3（§9.6）。所有者的逐项授权须写明：绑定的申请与 Q2、动作、范围，以及（如有）授权自身的截止时间和次数。

AR-B-010 的逐项授权只对它所绑定的那一条记录链有效。M 改变后形成的新链，必须重新申请；旧授权即使未被标记撤回，也不能配用于新链。

## 十二、事后抽查（对应 NB1、NB-01、N-02）

1. **范围：** 每个自然季度（北京时间）内作出处置的候选。季度标识写作 `YYYYQn`，例如 `2026Q4`。
2. **冻结清单：** 季度结束后，复核人形成该季度的候选清单并计算其 SHA-256；之后抽查只针对这份冻结清单。
3. **版本与多次处置：** 同一候选的多个版本，只计最后一个作出处置的版本；同一版本有多次处置的，取形成时间最晚的 R，时间相同的取 R 的 SHA-256 较小者。
4. **数量：** n = 向上取整（冻结清单中的候选数 × 10%），且不少于 2；不足 2 份的全部抽查。
5. **唯一选样算法：**
   1. 种子 = SHA-256（UTF-8 字节 `C03-AR-B-005-SAMPLE|` + 季度标识），取 64 位大写十六进制。
   2. 每个候选的分值 = SHA-256（UTF-8 字节 种子 + `|` + 候选代号），取 64 位大写十六进制。
   3. 分成三组，依次抽取：第一组为出现过停点或记录过"实质修正"的 L2 候选系列，第二组为其余 L2，第三组为 L1。每组内按分值升序排序；分值相同时按候选代号的 Unicode 码位升序。
   4. 依次从第一、二、三组取，直到取满 n 份或取完。
6. **抽查者：**
   - L2 样本：优先复查已留存的原 X 与记录链；或经所有者同意的同行律师。**同一 M 的 D 或其等效包，不得以抽查为名再次发送**，无论用途是什么。如另做跨模型审计，审计对象须与原送检内容不同、由所有者按 §七 单独准入，结果与原裁定隔离，只用于改进，不改写原裁定。没有安全路径的，记为"未完成抽查"。
   - L1 样本：L1 没有外发准入，§七 的范围不能默认为 L1 外发许可。只有所有者为该样本另行按 §七 规则批准外发的，才可交跨模型检查；否则由经所有者同意的同行律师抽查。
   - 没有获准路径的样本，记为"未完成抽查"并说明原因，不得用其他样本替代，也不得改由复核人自查后记为完成。
7. **留痕：** 冻结清单及其 SHA-256、种子、全部分值、抽取结果写入私有记录。同一季度、同一冻结清单必然得到同一结果。
8. **结果：** 只用于改进。尚未执行的事项仍按 R2 §十 处理撤回；已执行的事项不自动改写历史，也不自动改变既有决定，发现问题时另行评估。发现系统性问题的，须修订本设计。

## 十三、仍然存在的局限

R2 采纳决定所列的局限**全部保留**：复核人身份与资格是本人声明；独立性只是部分独立；复核人参与了输入的准备。此外：

1. 复核与放行的最终决定权仍在一人。R3 只是**拟缓解**，没有消除集中。在实际控制有证据之前，记录时一律写"拟缓解，未验证"。
2. **V8 采纳并正式运行之前，R3 新增的控制没有代码强制**（R2 已有的代码保护继续有效）。 记录是否当时形成、24 小时是否真的经过、Q 是否真的当时重查、发送前核对是否真的做了，都只靠复核人自律。
3. 同一律师的两个时点不等于两名独立复核人。
4. 交叉检查只看脱敏材料。对脱敏盲区的子判断，交叉检查**没有提供任何独立检查**；这些部分仍只依赖复核人一人。
5. 跨模型检查与生成模型也可能犯同样的错。
6. "实质修正"和"实质相关"是否成立，由复核人判断；停点索引能让判断留痕，但偏差只能靠抽查事后发现。
7. 发送前核对旨在降低错误外发的风险，未经运行验证；已经发生的外发无法收回。
8. 此前各轮审查中，有同模型审查，也有四轮 Codex 跨模型设计审查；均为文本审查，不是对实际运行的验证。本稿不改写这一历史。
