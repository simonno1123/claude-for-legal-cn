## 一、基本声明

1. 复核人的处置**不是法律意见**，不是对候选内容的背书，也不表示复核人认可其中的结论。处置只说明这一份候选能否另行申请下一步。
2. 任何处置，包括 APPROVE：
   - 都**不会激活 C03**；
   - 都**不会执行**这份候选；
   - 都**不会让任何外部服务获得授权**；
   - 都**不构成**对下游的长期授权。
3. 是否接受和解、是否申请拍卖、是否移送公安等委托人利益的取舍，**完全在 C03 之外**。这些不是本关口的后续步骤，APPROVE 不能作为这些决定的依据。

## 二、角色

| 角色 | 担任者 | 职责 |
| --- | --- | --- |
| 生成者 | C03 能力层（由 Claude 运行） | 只生成候选输出，状态固定为"待人工复核，下游阻断" |
| 复核人 | 合格执业律师，治理代号 `REVIEWER-01` | 按第五节的清单复核一份具体候选，作出 4 种处置之一 |
| 下游授权人 | 所有者（通过 AR-B-010 逐项授权） | 决定一份已获 APPROVE 的候选能否进入下一步 |
| 记录人 | Claude | 只记录，不复核，不授权 |

角色与设计版本绑定。复核包必须写明设计代号、版本、SHA-256 和清单版本。设计修订后，此后的复核按新版本进行；已作出的处置不追溯调整。

## 三、取值 A：只有一名执业律师时的职责集中（待所有者确认）

**现状。** 本项目只有一名执业律师，就是所有者。`REVIEWER-01` 由所有者担任，下游授权人也是所有者。

**独立性只能本人声明，无法验证，而且只是部分独立。**
- 候选由 C03 生成，不由所有者生成。
- 但候选依赖的输入，大多是所有者提供或确认的：案件包、证据矩阵、依据时效包，以及候选的目的。
- 因此所有者复核这类候选时，有一部分是在复核自己提供的输入。
- 复核和下游授权由同一人担任；第八节排除在关口之外的事项，最终也由同一人决定。

**两种处理方式：**
- **方式一：接受集中。** 在 E-006 中，把上述情况记为"已接受的局限"，而不是"已满足"。
- **方式二：重要候选另设第二复核人。** 第二复核人须为同所的其他执业律师。启用前须完成三件事：
  1. 确认委托人同意，或律所的保密安排允许；
  2. 对第二复核人单独做利益冲突检查；
  3. 第二复核人另行出具独立性声明。

**纠正只能重新生成。** 处置为 REQUEST CORRECTION 时，只能由 C03 重新生成一个新版本，并重新出具复核包。任何人都不得手工修改候选。人一旦改过候选，就不能再复核它；在方式一下没有其他复核人，处置只能是 KEEP BLOCKED。

## 四、资格与独立性（E-006 复核人独立性记录）

每次复核前，复核人逐项**签署声明**。任何一项不能声明，复核关口即阻断。

1. **资格。** 本人现在执业，执业证有效。资格依据的参考代号为 `QUAL-REF-01`；执业证信息只记在所有者本机，不进入公开仓库。
2. **角色与来源分离。** 本人是人，不是 AI、自动化程序或任何外部服务；本人的角色和身份明确。
3. **非自我复核。** 本人没有生成过这份候选，也没有修改过它。
4. **输入参与情况。** 如实写明本人对候选所依赖的输入做了什么：提供、确认，还是没有参与。方式一下，这一项作为已接受的局限记录。
5. **利益冲突。** 不存在未处理的利益冲突。本案代理律师复核本案候选，作为局限列明，不写成"不构成冲突"。
6. **知情。** 本人知道这份候选的局限和禁止用途。

资格、独立性或输入参与情况发生变化时，此前作出的处置自动失效。

## 五、复核清单（封闭清单 `CL-005-R2`）

任何一项不能勾选为"通过"，处置只能是 REJECT、REQUEST CORRECTION 或 KEEP BLOCKED。

| # | 检查项 |
| --- | --- |
| C1 | 案件代号与版本正确；项目、会话和外部服务都一致；没有混入其他案件的材料 |
| C2 | 引用的每一项材料都有登记代号和 SHA-256，并且在证据矩阵中可用 |
| C3 | 每一条事实都注明出处；OCR 或提取的文本没有被当作事实 |
| C4 | 引用的法律依据都在依据时效包中。写明时效包的核对日期；处置的有效期不得晚于该日期后 30 日 |
| C5 | 写明事实快照的日期。与期限有关的事项都已标出，例如申请执行期限、执行异议与复议期限、查封冻结期限；已届满或即将届满的必须明示 |
| C6 | 候选的类别在允许范围内，实质上也不属于 §16.2 的禁止类别，尤其不能是财产查找或追踪的指引，也不能是执行策略或战术 |
| C7 | 没有给出法律结论、胜诉判断或对外意见；没有提出或暗示任何有法律后果的动作 |
| C8 | 四项强制提示齐全，且没有被改动 |
| C9 | 冲突、局限、遗漏和不利情况都已列明，没有被隐藏 |
| C10 | 个人信息最少化：敏感个人信息（证件号、银行账号、财产信息）和案外人的信息，只在完成目的所必需时出现 |
| C11 | 输入和输出的 SHA-256 与复核包一致 |

## 六、复核包内容（packet contract）

每一份待复核的候选，复核包必须包括下表各项。缺少任何一项，或者复核过程中候选被修改，复核关口即阻断。

| 类别 | 内容 |
| --- | --- |
| 候选身份 | 候选代号、版本、输出 SHA-256、生成时间；候选类别；能力引用与操作类型 |
| 案件与目的 | 案件代号与版本；这份候选要服务的具体目的 |
| 追溯引用 | 每一项输入材料的代号与 SHA-256；合同引用与映射追溯引用；遗漏、冲突和不利情况的引用；失败与审计记录的引用 |
| 依据 | 依据时效包中对应的条目，以及该包的核对日期 |
| 撤回状态 | 这份候选及其输入有没有被撤回 |
| 复核范围 | 复核人实际审查了什么（例如"只审 C1 至 C11"或"另外审了事实部分"），没有审查什么 |
| 复核人 | 复核人代号；资格参考代号；当次的独立性声明（第四节） |
| 设计版本 | 设计代号、版本、SHA-256；清单版本 |
| 结果 | 清单的勾选结果；处置结果、理由、日期；处置的有效期（见 C4） |

## 七、处置

处置只有以下 4 种，原文照用：

```text
REJECT
REQUEST CORRECTION
KEEP BLOCKED
APPROVE A SPECIFIC CANDIDATE FOR A SEPARATELY AUTHORIZED NEXT STEP
```

- APPROVE 只表示"可以另行申请下一步"。下游仍然阻断，要等 AR-B-010 的逐项授权。
- 处置只对这一份候选、这一个版本、这一份复核包有效。以下任一情况发生，处置即失效：
  - 候选被取代或修改；
  - 依据过期；
  - 期限事项发生变化。
- **代码现状。** V6 只做到两点：
  1. 校验处置文字是否为上述 4 种原文之一；
  2. 保证 APPROVE 之后下游仍然阻断。

  以下几项代码**尚未实现**，目前靠复核包和记录来保证：
  - 把处置与候选的代号、版本、SHA-256 绑定；
  - 处置的失效；
  - 校验复核人身份。

## 八、升级边界

以下事项不在复核关口中决定：
- 对外发送、提交、签署、付款、披露，以及任何会产生法律后果的动作；
- 委托人利益的取舍（见第一节第 3 点）；
- 判断另一个案件的材料；
- 改变复核规则本身。改规则必须修订本设计，重新审查、重新采纳。

方式一下，这些事项最终由所有者本人决定，而所有者也是复核人。本设计不把这种情形当作"升级"，只是把这些事项排除在关口之外。

## 九、留痕

- 复核记录保存在所有者本机的私有目录，按案件分开存放。复核记录包括：复核包、独立性声明、勾选结果和处置。
- 公开仓库只记录以下几项：
  - 候选代号；
  - 处置结果；
  - 日期；
  - 复核人代号；
  - 清单是否全部通过。

  候选代号和处置理由中都不得含有能识别案件或个人的信息。

## 十、失败即关闭与撤回

**失败即关闭。** 出现以下任一情况，复核关口阻断：
- 复核人复核的是自己生成或修改过的内容；
- 复核人的角色或来源不清，包括由 AI 或外部服务充当复核人；
- 资格缺失；
- 复核包不完整；
- 存在未解决的重大冲突；
- 设计版本不符。

**撤回。** 出现以下任一情况，此前作出的处置失效：
- 资格、独立性或输入参与情况发生变化；
- 复核包被修改；
- 候选被取代；
- 复核被撤销；
- 依据过期，或期限事项发生变化。
