## 一、执行方式（所有替代控制的前提）

案件级执行只按下列方式进行；任何一条不满足，本处置对该次执行不适用，执行不得开始：

1. **只在所有者本机运行。** C03 代码在所有者电脑上以前台方式运行，案件材料只在所有者的私有文件夹中，不进入公开仓库。
2. **不接外部 Provider。** C03 代码本身不调用任何外部模型、网络服务或第三方接口。候选内容仍由记录人在代码之外起草，并照旧经 R3 人工关口、V8-A 记录校验和 AR-B-010 逐项授权（E-014 §五之二 V-015 说明）。
3. **一次授权，只跑一次。** 每一份 Tier B 授权包只对应一次运行；不重试、不排期、不在后台运行。
4. **所有者在场。** 运行期间所有者可以在对话中随时叫停。
5. **另存审计记录。** 每次运行在所有者本机的私有文件夹中另存一份只追加的审计记录（见第三节）。

## 二、逐项处置

"替代控制"指用上面的执行方式或手工步骤代替尚未验证的运行时机制；"接受的局限"指替代之后仍然存在、需要所有者明确接受的部分。

## 三、本机审计记录

- 位置：所有者私有文件夹中该案件目录下，不提交到仓库。
- 格式：每行一条 JSON，只追加，不修改、不删除；更正以新增一行更正记录表示（沿用 R3 的 CORR 做法）。每行附上一行内容的 SHA-256，形成简单链；所有者可随时用工具重算核对。
- **逐事件记录**（对应 WP-009 §15、计划 §7.9）：不仅记运行级摘要，每个控制事件各写一行。控制事件至少包括：运行开始；环境与 SHA 比对（B-09）；查重（B-02）；每次时刻核对（B-04）；拒绝；失败；超时与迟到结果处置；叫停；中断作废；中间文件隔离；转换结果复核（B-10）；每个输出的产生与交付；运行结束。
- 每个事件行至少包含：事件类型；运行编号；确切行为人（所有者或记录人）；记录时刻；前状态与后状态；理由；结果；所依据的决定或记录引用（Tier B 授权包 SHA、AR-B-010 决定、R3 记录 ID 等，没有则写明“无”）；前一行的 SHA-256。涉及输出的，另记输出文件的 SHA-256。
- 一次运行的记录以“运行结束”事件闭合，写明结束方式（完成、失败、超时隔离、叫停、中断作废）。未闭合的运行一律视为作废。

## 四、不改变的事项

- 调用关口仍然关闭；本处置不替代 Tier B 授权包，也不替代 AR-B-010 逐项授权。
- E-014 §五之二中的 A 类、C 类处理意见不变；截断审计链的修正仍留待集成阶段。
- 依据时效：每次案件级操作开始时须有在有效期内的依据时效包（依据时效范围修订）。
- 本处置只适用于 CASE-D。执行方式发生变化（例如要接外部 Provider、要后台运行）的，本处置对该变化部分不适用，须重新处置。

## 五、叫停与中断后的收尾

- 叫停后允许、且只允许记录人做下列收尾动作：①向审计记录追加“叫停”事件；②清点本次运行已产生的中间文件和输出，移入该案件目录下的作废文件夹（只移动，不删除），并逐个追加“隔离”事件；③追加“运行结束（叫停）”事件闭合记录；④向所有者报告收尾清单。
- 收尾动作不读取案件材料内容、不运行 C03 代码、不产生任何业务输出。
- 所有者也可以要求记录人连收尾也不做。此时由所有者手工完成上述步骤，或在下一次会话开始时由所有者指示记录人补做；补做的记录写明补记时刻和补记原因。在收尾完成并经所有者确认之前，该案件不得开始新的运行。
- 中断（例如连接断开、对话关闭）后，按同样步骤在下一次会话开始时补做收尾。
