## 1. 检查到使用的防替换：两层强制来源

### 第 1 层：目录权限（NTFS 访问控制 + 用户账户控制）

把验证用运行时放到一个只有管理员能写的专用目录（例如全体用户安装到 `Program Files`，或复制到一个新建的专用目录），并设置访问控制：

- SYSTEM 和 Administrators：完全控制；
- 运行验证的账户：只有读取和执行；
- 关闭从上级目录继承的权限。

强制来源是 Windows 的 NTFS 访问控制列表，加上用户账户控制。即使所有者账户属于管理员组，普通（未提权）进程也写不进去。

剩余限制：以管理员身份提权运行的进程仍然可以替换文件或改权限。所以 T0 要记录一份访问控制快照的散列，并在运行结束后再核对一次。

### 第 2 层：运行期间持有文件句柄（锁住）

外层监督进程在 T0 核验完、启动 Python 之前，以"只允许他人读取、禁止写入和删除"的共享方式打开全部绑定文件，并一直持有到 Python 退出。在 Windows 上，这样打开的文件不能被任何进程改写、删除或改名，所在目录也不能改名。

强制来源是 Windows 的文件共享模式。它覆盖的正好是"检查之后、使用之前"这段时间，这是第 1 层覆盖不到的。

剩余限制：内核级或离线（关机后）修改不在覆盖范围内。持有句柄只保护被打开的文件，所以绑定清单必须完整。

### 字节码缓存

启动参数加上 `-X pycache_prefix=<本次运行专用的空目录>`，并保留 `-B`。这样解释器既不会读取 Lib 里的 `__pycache__`，也不会写入新的缓存，每个源文件都会从已锁定的源码编译。T0 要核验这个前缀目录是空的。

### 冻结模块

冻结模块的代码就在 `python312.dll` 里面，`python312.dll` 的 SHA 绑定了，冻结模块也就绑定了。不需要关闭冻结模块，只需要在记录里写明这一点。

## 2. T0：在 Python 启动之前、在解释器之外的核验

T0 由外层监督进程完成。仓库里已有的外层监督候选（`DSP_004_CAPTURE_RESULT_OUTER_SUPERVISOR_CANDIDATE_REV2.cs`）已经接收一个外部 T0 时间点作为截止时间的起点。本设计规定 T0 之前必须依次完成：

1. 读取绑定清单：运行时 PE 文件、导入时闭包里的 Lib 文件、按名加载的编码模块、Harness 与受测文件、本次实际加载的系统 DLL；
2. 逐个计算 SHA，与清单比对，任何一项不符就阻止启动；
3. 记录运行时目录的访问控制快照散列，核验字节码前缀目录为空；
4. 按第 1 节第 2 层打开并持有全部绑定文件；
5. 记录单调时钟时间作为 T0；
6. 用固定参数启动：`python.exe -I -S -B -X pycache_prefix=<空目录> <固定入口>`，不读取额外命令行参数、环境变量或标准输入。

系统 DLL 由监督进程自己读取，不经过文件桥，所以不受 REV19 遇到的硬链接拒读影响。

剩余限制：监督进程本身的可信度来自所有者的操作系统和 .NET 运行时。它的源码必须先审查，编译产物的 SHA 必须先绑定。

## 3. 两侧调用身份

| 一侧 | 记录什么 | 怎么核对 |
| --- | --- | --- |
| 调用方（监督进程） | 自身映像路径和 SHA、进程号、启动参数 | 进程号和映像 SHA 写入运行记录 |
| 被调用方（Python） | 启动时得到的进程号；系统查询到的主映像路径；子进程回传的 `sys.executable` 和一次性随机数 | 主映像路径要等于已锁定的 `python.exe`；子进程的父进程号要等于监督进程号；随机数要原样回传 |

一次性随机数由监督进程生成，只通过已绑定的管道传给子进程。这样就能证明回报来自这一次启动的这个子进程。
