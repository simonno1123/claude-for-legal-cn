## 一、目的与范围

R3 新增的控制目前全靠复核人自律（R3 §十三 第 2 项）。试跑又说明，人工逐项填写负担过重，多选题容易漏点（TF-01、TF-02）。V8 的目的有两个：

1. **校验：** 用代码检查 R3 记录是否齐全、引用链是否完整、先后顺序是否正确、规则是否满足。不满足的一律阻断，并给出理由码。
2. **减负：** 机械性字段（哈希、有效截止、引用）由工具计算并预填。复核人只需对需要判断的项逐项作答，记录人把答复原样转录成记录。

V8 分两期：

| 分期 | 内容 | 本稿 |
| --- | --- | --- |
| **V8-A** | 记录合同、纯函数校验器、本机命令行包装、记录生成辅助、测试用例 | 本稿完整设计，采纳后实现 |
| **V8-B** | 数字签名、信任根、可信时间、跨次调用防重放 | 只列要求（第九节），**暂缓**。理由见第九节 |

## 二、原则

1. **AI 不是复核人。** V8 只检查记录、计算机械字段，不作任何判断或处置。记录生成辅助只转录复核人的答复，不替复核人作答。
2. **R3 是规则来源。** V8 只把 R3 已有的规则写成代码，不新增或放宽规则。代码与 R3 冲突时，以 R3 为准，并修订代码。
3. **核心是纯函数。** 校验器不读时钟、不访问网络、不读写文件，只接收内存中的记录并返回结果。读取本机目录、获取当前时间由外层命令行包装负责。
4. **不确定即阻断。** 缺字段、多字段、类型不符、无法解析、引用对不上，一律阻断。
5. **最大正面结果**是 `ELIGIBLE_TO_REQUEST_AR_B_010`，即"可以另行申请 AR-B-010"。这个结果不是授权，不执行任何动作，也不解锁下游。
6. **真实材料不进仓库。** 代码和测试只用虚构数据；真实记录只在所有者本机运行。
7. **R2 已有的代码保护**（处置原文检查、候选保持待人工复核、下游阻断）原样保留，V8 不改动它们。

## 四、记录格式

### 4.1 共同规则（对应 TF-04）

- 每份记录是一个 JSON 对象，含 `record`（记录种类）和 `schema`（`C03-V8-R1`）两个字段。
- 解析时拒绝：重复键、非法 JSON、浮点数（金额一律用整数"分"或字符串）、合同之外的字段、缺少的必填字段。
- 规范化：键按 Unicode 码位排序，无多余空白，UTF-8 编码。在不含浮点数的前提下，这与 RFC 8785（JCS）的结果相同。记录的 SHA-256 一律按规范化字节计算，写成 64 位大写十六进制。
- 时间：带明确时区偏移的 ISO 8601，按真实日历解析（R3 §9.1）。
- 每份记录写明它引用的前件的 SHA-256，并带 `formed_at`（形成时间）与 `method`（形成方式：`file_a`、`file_b`、`chat_c`，对应 R3 §3.1 的三种方式）。

## 五、校验规则与理由码

校验器按下表顺序检查，**列出全部未满足的规则**（不在第一条失败处停止），按顺序输出理由码。只要有任一理由码，结果就是阻断。

| 顺序 | 规则 | 理由码 | R3 出处 |
| --- | --- | --- | --- |
| 1 | 每份记录可解析、合同完整、无多余字段、无浮点数 | `RECORD_INVALID` | §3.4 |
| 2 | 设计版本三元组与采纳的 R3 一致 | `DESIGN_VERSION_MISMATCH` | §3.5 |
| 3 | 引用链完整：前件存在、SHA 一致、无环 | `CHAIN_BROKEN`（前件缺失或引用错误）／`BINDING_MISMATCH`（前件存在但内容不符） | §3.3 |
| 4 | M 中没有事后字段 | `M_CONTAINS_POST_REVIEW_FIELD` | §3.2 |
| 5 | I 六项全部确认，且形成时间早于 T | `PRE_REVIEW_DECLARATION_INVALID` | §3.2 |
| 6 | 组合在允许用途表内；无已知禁止目的 | `PURPOSE_PROHIBITED` | §4.2、§4.4 第 1 项 |
| 7 | T 存在且字段一致；L1 有正面确认 | `TIER_INVALID` | §4.4 第 2 项 |

| 9 | 输出类别在 WP-007 §16.1 允许集合内 | `OUTPUT_CLASS_NOT_PERMITTED` | §4.2 |

| 11 | （L2）同一 M 只有一份 S；没有等效重送标记 | `RESEND_DETECTED` | §6.5 第 1 项 |
| 12 | （L2）X 覆盖 C1–C11 全部，取值合法，盲区只用于允许的子判断 | `CROSS_CHECK_INCOMPLETE` | §6.2 |

| 17 | C1–C11 全部通过（计入更正记录）；C11 有原包核验 | `CHECKLIST_NOT_ALL_PASS` | R2 §五、§7.7 |
| 18 | 无未解决的重大冲突；无撤回 | `MATERIAL_CONFLICT_OPEN`／`WITHDRAWN_OR_SUPERSEDED` | R2 §十 |
| 19 | C5 无 `未知` 期限；没有期限时有正面声明 | `DEADLINE_STATUS_UNKNOWN` | §9.2 |
| 20 | 有效截止按 §9.2 重新计算，与记录相同 | `VALIDITY_CUTOFF_MISMATCH` | §9.2 |
| 21 | （L2）X 收件 < R < P；P − R ≥ 24 小时；P < 有效截止；P 五项齐全 | `EVENT_ORDER_INVALID`／`COOLING_PERIOD_UNMET`／`RECONFIRMATION_MISSING` | §9.4、§9.5 |
| 22 | 当前时间（由包装传入）早于有效截止 | `VALIDITY_EXPIRED` | §9.2、§9.6 |

| 阶段 | 返回值 |
| --- | --- |
| 复核完成（L1 有 R；L2 有 R、P） | `ELIGIBLE_TO_REQUEST_AR_B_010` |
| 申请前（有 Q1） | `APPLICATION_RECORDS_COMPLETE` |

## 六、代码做不到的事（外侧责任）

V8-A 只检查记录本身。下列事实只能以复核人或所有者的记录作为输入，代码无法核实其真实性：

| 事实 | V8-A 的处理 | 局限 |
| --- | --- | --- |
| 记录是否当时形成，时间是否真实 | 只检查格式、先后顺序和间隔 | 无法防止倒填（R3 §十三 第 2 项） |
| 24 小时是否真的等过 | 只比较记录中的时间 | 同上 |
| 交叉检查模型的真实来源 | 只比较申报值 | 第 13 条依赖申报 |
| 发送前核对是否真的做了 | 只检查 S 中的核对结果 | 依赖复核人 |
| 撤回是否已传到记录里 | 只读已记录的撤回状态 | 遗漏的撤回无法发现 |
| 跨次调用是否重放 | 只检查本次输入内部 | 跨次防重放属于 V8-B |

## 七、记录生成辅助（对应 TF-01、TF-02、TF-03）

1. **预填机械字段：** 哈希、引用、有效截止、期限清单骨架、H 查询结果和增量核对的最后事件，都由工具计算。
2. **判断项逐项单选：** 凡是 I 的六项、T 的正面确认、C1–C11 各项、P 的五项、Q 对照表的各行，每项都单独作答（`确认`／`不确认`，或 `通过`／`不通过`）。不再用多选题，避免漏点（TF-02）。
3. **转录：** 记录人把复核人在对话中的答复原样写入记录，`method` 记为 `chat_c`。答复不完整时，工具拒绝生成记录。
4. **时间：** 对话界面不提供每题的答复时间，因此 `formed_at` 记为转录时间，另记答复的先后顺序（TF-03）。这是局限，不是可信时间。
5. **更正：** 发现点选遗漏时，只能追加更正记录并在 H 中追加解除事件，不改动原记录（试跑实践）。

## 八、测试

1. 每个 R3 附录 A 反例（A-01 至 A-77），只要可以表示为记录输入，就做成一组虚构测试数据，并写明预期理由码。只能靠人工判断、无法用记录表示的反例，在测试清单中列明"不由代码覆盖"及原因。
2. 至少一条完整的 L1 正向路径和一条完整的 L2 正向路径，预期返回 `ELIGIBLE_TO_REQUEST_AR_B_010`。
3. 试跑形成的记录结构，用虚构数据再现一遍（含点选遗漏和更正），预期结果为 `DEADLINE_STATUS_UNKNOWN` 加 `DISPOSITION_NOT_APPROVE`。
4. 校验器的纯函数性质：测试中不提供时钟、文件或网络，核心函数也必须能运行。
5. 测试接入仓库现有的 CI。

## 九、V8-B：暂缓的事项

R3 §十 移交的以下要求留到 V8-B：

1. 可信时间与调用新鲜度：挑战值；快照时间满足 `R/P < 快照 ≤ 当前 < 有效截止`。
2. 信任根与数字签名：受控入口固定公钥、算法、角色；规定各类记录的签名覆盖范围。
3. 可验证的模型来源。
4. 跨次调用的防重放，以及一次性使用登记。
5. AR-B-010 执行边界的独立重验。

**暂缓的理由：** 本项目只有一名执业律师，签名密钥、时间来源和撤回登记都由同一人掌握。V8-B 能防止记录被篡改或重放，但不能消除一人集中，实施和维护成本也高。所有者可以在 V8-A 运行一段时间后，再决定是否启动 V8-B。V8-B 启动之前，第六节所列局限继续有效。

## 十、实施与治理

1. 本稿交 Codex 做一轮跨模型复核。阻断项修改后，再做一轮定向确认，之后不再送审（沿用 R3 的停止规则），由所有者决定是否采纳。
2. 采纳后在功能分支实现，测试全部通过、合并后，在所有者本机对试跑的真实记录跑一次。结果只记入私有目录，仓库只记脱敏状态。
3. V8-A 运行之后，R3 §十三 第 2 项改为："第六节所列事项仍靠自律；其余由 V8-A 校验"。

## 十一、局限

1. V8-A 不能证明记录内容真实，只能检查一致性和规则。
2. 一人集中未消除。
3. 测试只覆盖可以用记录表示的反例。
4. 本稿是草稿，未经复核，也未实现。
