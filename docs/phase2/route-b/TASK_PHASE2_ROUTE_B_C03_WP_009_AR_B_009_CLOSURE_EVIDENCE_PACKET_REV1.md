| 所有者验收 | — | **待所有者决定** |

关闭失败条件逐项说明：
- **不会静默重试或回退**：重试只能到"待定"状态，不会执行。
- **不会重复产生效果**：重复调用一律拒绝。
- **不会覆盖状态**：所有记录都不可变。
- **撤销不会遗漏**：判定时终止、撤销优先于其他一切。
- **审计可核验**：审计链可以重新计算。
- **回滚范围不会扩大**：恢复范围必须有界，且审计历史必须列为禁止恢复的对象。

## 三、需要所有者知道的几点

- **只验证了判定逻辑。** 计时器、信号传播、持久化的记录、真实依赖都没有被观察；设计本身也规定不实现这些。
- **判定函数还没有接入 `capability.py`。** 设计要求"每一次重要转换之前都要判定"，目前没有代码路径强制执行这一点。将来接入时，需要另行授权和验证。
- **判定依据由调用方提供**：时间、作用范围、已接受版本清单、决定是否有效，都由调用方给出，函数本身不核实。
- **全部审查都是同一模型家族的子代理**，没有外部审查。

## 四、AR-B-008（运行验证）现状评估

计划 §7.8 对 AR-B-008 的要求如下：
- **前置条件**：WP-007 与 WP-009 的实现都已被接受。WP-007 的 V4 已验收；V5 一旦验收，这个条件即满足。
- **退出门禁**：身份、正向、负向、隔离、失败、重试、恢复、撤销、审计、边界各类情形，都经过独立审查并被接受。

正式运行 v4 共 70 个变体，按场景的覆盖等级如下：

| 覆盖等级 | 场景 |
| --- | --- |
| 完全（FULL） | V-001、002、003、005、007、014 |
| 部分（PARTIAL_LIMITED） | V-004、006、008、009、010、011、012、013 |
| 仅观察（OBSERVE_ONLY_LIMITED） | V-015（分类边界） |

**结论：AR-B-008 还不满足"全部情形都被接受"的字面要求。** 原因有两条：
1. V-015 仍只能观察，分类边界需要另做设计（RDM-DSP-012）。
2. 8 个部分覆盖的场景依赖运行时机制（计时、信号、持久化），这些机制按设计不在能力层实现。

**可选的处理方式（由所有者决定）：**
- **继续保持开放**：等补上 V-015 的分类边界设计；运行时部分留到实际业务域选定之后。
- **带局限关闭**：明确记下上述局限，以"仅限判定逻辑"作为关闭范围。但这偏离计划 §7.8 的退出门禁，属于需要所有者明确承担的偏离。

记录人的建议：先关闭 AR-B-009，AR-B-008 暂时保持开放，接下来补 V-015 的分类边界。
