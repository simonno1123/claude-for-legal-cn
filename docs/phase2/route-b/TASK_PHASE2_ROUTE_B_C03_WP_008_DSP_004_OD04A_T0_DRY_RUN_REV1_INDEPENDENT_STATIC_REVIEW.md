# DSP-004 OD04-A T0 演练 REV1 独立静态复核

本复核由一个未参与编写的独立复核者完成。复核者是新开的 Claude 子任务，只拿到仓库中的代码、记录、设计和验证执行包 V3.2，看不到记录人的编写过程。复核者与记录人属于同一模型家族，这是独立性的限制。复核时没有修改文件，没有在 Windows 上运行任何东西，也没有联网。

结论：**不能把这次演练准入为 OD-04 证据。** 最多只能记为"非证据性的工程演练观察"，并把 IR-01 至 IR-11 写成明确限制。

`Signed` 与 `Accepted` 都是 false。准入是 `NOT_ADMITTED`。DSP-004 保持 `OPEN / HOLD`。

## 1. 复核确认成立的部分

- 8 个资产文件的 SHA 和字节数与结果记录一致。
- 绑定清单与第 ①步的设置结果完全一致：653 个文件，路径、字节、SHA 都相同。
- REV19 记录的 113 个 SHA 都在绑定清单里。
- 子进程加载的 30 个原生模块，恰好是 22 个系统 DLL 加 8 个运行时文件。
- 监督程序确实是先锁文件、再透过句柄散列。

也就是说，数字内部是一致的；问题在于这些数字能证明什么。

## 2. 发现摘要

| 编号 | 级别 | 要点 |
| --- | --- | --- |
| IR-01 | 阻止准入 | 信任根是监督程序自己报告自己。监督程序、绑定清单和启动器都放在用户可写的目录里，运行前没有绑定；`powershell.exe` 按名称查找，可能被替换；当前用户的模块路径可以替换 `Get-FileHash` 等命令。这正是 PF-003 和 V3.2 §4.2 排除的情形 |
| IR-02 | 需写明限制 | 15 项核对中有 10 项是子进程自己的说法，只有 5 项由监督程序从外部核对。若模块枚举失败，"全部在清单内"会对空列表通过；`__main__` 没有和被锁的探测脚本比对；`PycachePrefixIsEmptyDir` 只是字符串比较 |
| IR-03 | 需写明限制 | 同一用户的普通进程就可以改写 Python 或监督程序的内存、注入线程。文件锁和访问控制保护的是文件，不是进程。剩余限制里只写了"提权或内核级"，说轻了 |
| IR-04 | 需写明限制 | 访问控制这一层要求以未提权的令牌运行，但没有记录提权状态、完整性级别或用户账户控制是否开启 |
| IR-05 | 需写明限制 | 加了 `-X pycache_prefix` 参数，并通过标准输入传随机数，这与 PF-004 和设计"不读取标准输入"不符；环境变量既没有清空也没有记录（例如 OpenSSL 的 `OPENSSL_CONF`、`PATH`）；`sys.path` 没有对照预期清单 |
| IR-06 | 需写明限制 | 只检查了源码加载器和原生模块，没有检查无源码字节码、`python312.zip`、命名空间包；运行后没有再扫描一次目录树；只核对了 4 个对象的访问控制，没有核对其余文件 |
| IR-07 | 需写明限制 | 多数系统 DLL 属于 KnownDLLs，是从开机时建立的内存段映射的，不是从被锁住的文件。锁文件和散列并不能绑定实际映射的内容 |
| IR-08 | 需写明限制 | 运行时的真实性只是"首次信任"：第 ①步只核对了源 `python.exe`，其余 652 个文件是从用户可写的安装目录复制来的；运行时 PE 文件的签名没有验证 |
| IR-09 | 需写明限制 | 设置结果里没有记录脚本 SHA 和时间戳，所以"提交的就是实际运行的版本"只是记录人的陈述；而且提权脚本是从用户可写目录运行的 |
| IR-10 | 需写明限制 | 第 ②步要求"审查后绑定 SHA"再做第 ③步。实际上监督程序的 SHA 是在演练之后才提交的（提交时间 02:16Z，T0 是 02:13Z），审查也只是记录人自审 |
| IR-11 | 需写明限制 | REV23 提交的脱敏副本是重新序列化的，不是在原文件上替换文字，无法用仓库里的内容证明它们对应所引用的原始 SHA |
| IR-12 | 次要 | 探测脚本位于用户可写路径，没有检查重解析点 |
| IR-13 | 次要 | "T0 在启动之前"只靠代码顺序证明；`StderrBytes` 统计的是字符数而不是字节数；其他小缺口 |
| IR-14 | 次要 | 读取和执行权限给的是整个 BUILTIN\Users 组，不是设计里说的"运行验证的账户" |
| IR-15 | 备注 | 结果文档在 T0 和两侧身份上说过头了，剩余限制漏列了 IR-03 至 IR-11 |
| IR-16 | 备注 | 所有者回复中的"合并"一词有歧义；授权时间是估计值 |
| IR-17 | 备注 | robocopy 排除的目录不构成访问控制上的弱点 |

## 3. 复核者给出的合格条件

要让这次演练成为 T0 和防替换的证据，至少需要：

1. 启动器在运行前绑定，放在管理员保护的位置，并核验宿主程序；
2. 监督程序从进程外部枚举子进程加载的模块；
3. 清空并记录环境变量，并与 PF-004 一致；
4. 记录令牌和用户账户控制的状态；
5. 运行后再扫描一次目录树，并逐个文件记录访问控制；
6. 原始记录可以用其引用的 SHA 核对，并经过独立复核。

## 4. 记录人对 IR-11 的即时处理

记录人另外提交了两份按字节替换生成的脱敏原始记录，替换规则写在机器记录里。所有者用本机的原始文件按同样规则替换，就能逐字节复现，从而核对引用的原始 SHA。这只解决了 IR-11 中"无法核对"的部分；REV23 的重新序列化副本保留不动，并已被注明不能作为原始记录的替代。
