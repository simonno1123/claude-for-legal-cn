# /review

## 强制规则

- 开始前完成下节画像与事项预检；画像缺失时提示运行 `/commercial-legal:cold-start-interview`，不自动初始化或静默绕过前置。
- 不按英文标题机械路由。必须识别主协议、订单、附件、SLA、DPA、补充协议、报价单、采购单之间的组合。
- 先确认我方身份：采购方、销售方、服务提供方、客户、披露方、接收方。
- 涉外、双语、境外仲裁、数据出境、外汇或出口管制必须标注专项复核。
- 前置读取 `references/china-approval-and-seal-policy.md`、`references/china-vendor-review-checklist.yaml`、`references/china-dispute-resolution.md`，先做用印授权、发票税务、争议解决三项红旗筛查。
- 红旗及风险等级用于升级和路由，不等于合同当然无效、已经越权或已产生税务违法后果。对实际作为风险判断依据的法律／司法解释列明名称、条号／文号、适用版本及可核查出处，未实际核验不得声称已核验。适用事实、法律版本、例外或程序条件未核实时，标题、正文及建议均应保留相应限制，不只在末尾附加“待查证”；风险消除或谈判建议不等于法律要求的唯一方案。

## 画像与事项预检

1. 保留既有状态根 `~/.claude/plugins/config/claude-for-legal/commercial-legal/`，确认本次获准的读取范围及宿主实际路径后，读取 `CLAUDE.md` 和存在的 `matters/index.yaml`。未获准读取、路径未确认或画像缺失时说明停点，不改用另一个目录或自动生成画像。
2. 索引不存在或 `enabled: false` 时，使用已有practice-level画像，不创建事项。读取／解析失败不能当作索引不存在；索引无效或画像中 `## Matter workspaces` 镜像与索引冲突时，暂停并请求澄清，不自动修复或降级。`matters/index.yaml` 是事项状态的唯一事实源。
3. 已启用但 `active_matter: null` 时，先询问继续使用practice-level还是切换到已有事项；不代选，不自动创建或切换事项。
4. 存在active matter时，先核对slug、索引路径和状态，再只读取该事项的 `matter.yaml` 及本次获准材料。路径越界、软链接穿越、目录缺失、状态冲突或事项已关闭／归档时暂停，不回退到其他事项或搜索其正文。默认 `cross_matter_context: false`；只有该设置已启用且用户另行明确比较范围时，才可比较指定事项。
5. 预检只读，不创建、启用、迁移或更新画像／事项／tracker。审阅输出的留存须另行预览并取得确认，实际写入成功后才记录 `output_recorded` 历史事件；不能把预检、路由或审阅完成当作写入授权或存储成功。

## 材料范围与缺件停点

- 列明本次实际提供的正文、订单、附件及版本；仅被提及而未提供的文件不能视为已读取。“未提供”不等于“未约定”，也不能借用未获准的其他事项、版本或历史输出补全。
- 为缺件或未知事实列出受影响的具体判断和补问。只暂停依赖该信息的判断；其余有现有文本支持的问题可继续识别并带范围限制路由，不一律终止整份审阅。
- 已有文本问题引用可核查的条号（如有）及原文片段；缺位条款、未提供材料或无编号文本说明已审范围和定位限制，不补造条号、引文或内容。

## 前置红旗筛查

1. **先票后款和税务损失**
   - 发现“收到发票后付款”“先票后款”“增值税专用发票”时，核对合同实际约定的发票种类、开具条件及其与付款、验收的关系；纳税人身份、抵扣条件和内部要求未知时提出补问，不默认专票或可抵扣性必须成为所有交易的付款前提。
   - 出现虚开、异常凭证、主体不一致或抵扣障碍等线索时，标明已知事实与待核事项并升级税务复核，路由 `vendor-agreement-review` 或 `saas-msa-review`；不得仅凭主体不一致就认定虚开或必然无法抵扣，也不据风险标签确认当前拒付权。

2. **用印授权和电子签**
   - 发现项目章、部门章、技术部章、采购部章、分公司章、办事处章、图片章、空白盖章合同、离职员工签约时，将印章真实性、签署身份与权限、追认及表见代理条件分别列作核验点；不得仅凭章型认定伪造、表见代理成立或合同无效。
   - 发现电子签时，必须要求核验可靠电子签名四要素；CA 证书、实名认证、签署意愿确认、时间戳、签署日志、文件哈希和签署完成证书作为证据增强项审查。

3. **争议解决路径与效力核查**
   - 发现“可向法院起诉或提交仲裁”“诉讼或仲裁”“或审或仲”时，保留P0升级提示（内部审查级别），按 `references/china-dispute-resolution.md` 分开核对仲裁约定、诉讼管辖约定及程序条件。可建议协商明确单一路径，不把建议当作普遍唯一法定形式，也不因仲裁约定有问题就自动否定法院管辖约定。
   - 发现“各自所在地法院”“原告所在地或被告所在地法院”等多地选择时，核对书面合意、地点的实际联系、起诉时能否依法确定法院及级别／专属／专门管辖限制；不能仅因约定多个法院就认定不确定或无效。只对实际缺失、冲突或未核实条件补问并升级，单一法院方案仅作为可协商选项。

## 路由规则

| 命中内容 | 路由 |
|---|---|
| 供应商、采购、服务采购、设备采购、外包 | `vendor-agreement-review` |
| 销售框架、销售服务协议、销售订单、经销/代理销售、客户采购条款 | `vendor-agreement-review`（按我方销售方/服务提供方视角审查） |
| SaaS、云服务、软件许可、API、平台服务、SLA、DPA | `saas-msa-review` |
| NDA、保密协议、商业秘密、技术交流、样品测试 | `nda-review` |
| 自动续约、到期、取消通知、涨价 | `renewal-tracker` |
| 补充协议、变更单、订单历史 | `amendment-history` |
| 非标条款、金额阈值、用印、数据、税务 | `escalation-flagger` |
